# MARKET_ANALYTICAL_EVIDENCE_SCHEMA_MAP_v1

## Scope and classification rules

This map covers the current `market.analysis.read` result envelope and analytical payload at `WORK_BRANCH_START_HEAD = bc34e973686d7f78b0e9c3efd67b433f0901f21a`.

- Source classes are limited to: `DIRECT_OBSERVED`, `DERIVED_MARKET_EVIDENCE`, `ANALYST_CLAIM`, `ANALYST_OPINION`, `APPROVAL_METADATA`, `QUALITY_METADATA`, `PROVENANCE_METADATA`, and `UNKNOWN`.
- `epistemic_status` is reported only where current code mechanically emits a field of that name. No hidden epistemic interpretation is invented.
- `trade_date/as_of semantics`: `trade_date` is the exact producer/market date. `as_of` is defaulted to that date at 15:30 China time (`UTC+08:00`) when the producer payload does not supply an explicit value; it is projection time semantics, not a separate date selector.
- Julia interpretation is required for market meaning, causal synthesis, applicability, and final judgment. Market is an evidence provider, not the final judgment authority.

## Evidence extraction inventory

`MarketEvidenceAdapter` emits only these producer fields:

| Module | Emitted analytical keys |
|---|---|
| `engine_summary` | `decision.allow_trade`, `decision.trade_mode`, `decision.blocking_rule`, `decision.position_limit`, `decision.next_day_strategy` |
| `market_regime_review` | `market.broad_market_regime`, `market.short_term_sentiment`, `market.mainline_environment` |
| `post_market_setup_plan` | `calendar.next_trade_date`; row `summary`, `focus`, `reason`, `rationale`; technical `focus`, `reason`, `rationale` |
| `watchlists` | indexed row `stock_name`, `stock_id`, `subject_key`, `summary`, `reason`, `watch_date`, `decision`, `setup_type` |
| `mainline_states` | indexed `name`, `lifecycle`, `state`, `strong_stock_count` |

Coverage is tracked for `engine_summary`, `market_regime_review`, `daily_recap_essentials`, `mainline_states`, `theme_reviews`, `limit_up_theme_events`, `new_high_summary`, `seat_money_summary`, `watchlists`, and `post_market_setup_plan`, but coverage alone is not evidence extraction. In particular, current `MarketEvidenceAdapter` does not extract content from `daily_recap_essentials`, `theme_reviews`, `limit_up_theme_events`, `new_high_summary`, or `seat_money_summary`.

## Source ownership caveat

The canonical recap payload does not carry a field-level producer-role marker for every analytical value. The projection can prove that values came from a module in the exact persisted snapshot, but absent upstream role metadata it cannot mechanically distinguish whether the underlying producer text was machine-derived or analyst-authored. Such values are therefore mapped as `DERIVED_MARKET_EVIDENCE` at the public projection layer; their original epistemic role is not inventable from this code.
