## 0. 为什么先做题材目录：现状里的四个问题

1. **工作台的个股表里，没有短线主线的龙头。** ✅
   7/1–9/24 的 62 份 `review_document.json` 里，海南海药、哈药股份、金健米业、万向德农、亚盛集团、新华传媒、新华文轩、华瓷股份、国芳集团、百大集团**一次都没有出现**。工作台跟踪的主要是机构方向的题材股。照现在的数据去算题材周期，正好会漏掉真正驱动周期的那几只股票。
2. **医药类题材在工作台里到 7/10 才出现。** ✅ 昊哥 6/23 就已经列出医药 14 只涨停（海南海药、新华制药、津药药业……）。
3. **工作台给题材打的阶段几乎全是 divergence。** ✅ 例如“医药医疗”24 天里有 21 天是 divergence。这样的阶段标签没有区分度。
4. **同一类东西有很多叫法，而且叫法并不只来自行业分类。**
   - 行业类：医药医疗 / 创新药 / 原料药 / CXO……（jyhf 主题）
   - 事件类：**“厄尔尼诺”**。8/17 昊哥写“厄尔尼诺第一天，龙头金健米业”；9/20 又写“电力这波其实也是炒的厄尔尼诺的分歧”。一个事件同时覆盖了农业和电力。
   - 叙事类：**“华字辈”**（华瓷、新华、文轩、华媒），横跨陶瓷、传媒和出版，任何行业表都装不下。
   - 简称：昊哥原文用“金健、万向、文轩、新华”，必须先解析成股票代码。

结论：题材目录必须带时间、记录来源、可以分层、支持多种题材类型；另外，“题材”和“主线周期的一段行情”要分成两个对象。

## 1. 数据对象

### 1.1 题材节点 `theme`

| 字段 | 说明 |
|---|---|
| canonical_theme_id | 稳定 ID，例如 `THM-MED`、`THM-ELNINO`、`THM-HUA-NARRATIVE` |
| canonical_name | 规范名称 |
| theme_type | `INDUSTRY` / `CONCEPT` / `EVENT` / `POLICY` / `NARRATIVE` / `STYLE` |
| theme_level | 0 = 大类，1 = 子类，2 = 细分 |
| parent_theme_ids[] | 可以有**多个上级**：事件或叙事题材可能同时挂在几个行业下面 |
| aliases[] | 别名和简称，例如“药”“医药”“创新药主线” |
| source_refs[] | 外部来源 ID，例如 `jyhf:1`、`jyhf:9025631`、`ths_tag:厄尔尼诺` |
| valid_from / valid_to | 这个题材节点本身的有效期 |
| merge_from[] / split_from[] | 合并、拆分的历史 |

### 1.2 成分关系 `theme_membership`（带时间，不是永久成员）

| 字段 | 说明 |
|---|---|
| stock_id, theme_id | — |
| membership_type | `DIRECT`（主营直接相关）/ `INDUSTRY_CHAIN` / `CONCEPT` / `MARKET_NARRATIVE`（市场叙事，例如“华字辈”） |
| valid_from / valid_to | 生效区间 |
| evidence_source | `jyhf_daily` / `ths_reason` / `analyst_text` / `owner` |
| evidence_ref, evidence_as_of | 证据位置，以及证据**当时**可见的时间 |
| confidence, claim_status | 置信度；`OFFICIAL` / `MEDIA` / `RUMOR` / `ANALYST_VIEW` |

### 1.3 主线周期片段 `mainline_episode`（新增）

**题材 ≠ 周期片段。** 同一个题材可以先后走好几段周期。比如医药：

- 第一段：6/23 启动 → 7/1 海南海药 7 天 5 板 → 7/14–7/16 哈药成为全市场最高板；
- 第二段：8/10–8/13 哈药“二波引领高度”，9/2 昊哥写“医药主升大概率结束转退潮”。

| 字段 | 说明 |
|---|---|
| episode_id | 例如 `EP-MED-2026A`、`EP-MED-2026B` |
| theme_id | 所属题材 |
| start_date / end_date | 开始、结束日期（结束日可以为空，表示仍在进行） |
| leader_trace[] | 龙头随时间的变化，例如 海南海药 → 哈药 |
| source_labels[] | 原文里的阶段说法和出处 |
| relation | 与上一段的关系：`NEW` / `SECOND_WAVE` / `SPIN_OFF` |

第一段和第二段到底是同一个周期里的“再次高潮”，还是两段独立的周期，由 Tony 裁定（见 §5 Q1）。

### 1.4 防止用到未来信息

```text
R-01  第 T 日能用的成分，只能来自 evidence_as_of ≤ T 的证据。
R-02  subject_stock_map 每个（题材，股票）只有一行，会被后来的数据覆盖，
      不能拿来推断历史成分，只能作参照。
R-03  分析师原文里的说法，有效时间从文章发布时间算起（周末文章对应上一个交易日收盘之后）。
R-04  不能因为某只股票后来成了龙头，就倒推它在之前某天已经属于这个题材。
R-05  叙事类成分（MARKET_NARRATIVE）只能来自当时的文字证据，不能按名字规则去补齐。
```

## 4. 只读提取脚本（需要 Tony 执行）

```bash
cd ~/Desktop/ai_theme_app/tmp/p0_theme_catalog
PGDATABASE=stock_data PGUSER=postgres ./extract_readonly.sh
```

- 会话级 `default_transaction_read_only = on`，不写任何表。脚本里不写密码，请用 `~/.pgpass` 或 `PGPASSWORD`。
- 输出到 `out/`，一共 7 个 CSV：
  - 两张覆盖度表：`subject_stock_daily_snapshot` 和 `ths_hot_reason_snapshot` 在 6/15–9/30 每天的行数；
  - 候选题材的逐日成分；
  - 试点龙头被 jyhf 归到了哪些题材（用来发现“厄尔尼诺”这类不在候选列表里的题材）；
  - 龙头的同花顺涨停原因；
  - 题材层级；
  - 静态映射（只作对照）。
- 如果数据库名不是 `stock_data`，改 `PGDATABASE` 就行。仓库里同时出现过 `stock_data` 和 `stock_data_test`，以你实际在用的那个为准。
