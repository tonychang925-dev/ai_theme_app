# 个人投资助理项目-前端技术设计（第四阶段前置版）

> 本文档用于将第四阶段前端工作中的一部分前置实施，优先交付一个类似久赢恒丰的“情报列表页”，把当天新闻事件、题材异动、新题材候选、关联股票集中可视化展示出来。

> 2026-03-31 补充说明：
> 本文档需与《个人投资助理-项目架构设计-第三阶段》修订版配套阅读。当前前置版前端的定位，不是直接长期消费 `theme_service` 的所有底层领域接口，而是先基于现有接口快速验证页面与交互；待第三阶段的 `frontend_bff / api_gateway` 落地后，前端应逐步切换到统一产品出口，避免页面层长期耦合到底层服务实现。

---

## 一、前置目标

### 1.1 当前前置范围

本次前置不追求完整交易终端，而是优先落地：

- `Intel Feed` 情报列表页
- `Theme Detail` 题材详情页
- `Theme History / Children / Stocks` 联动面板

### 1.2 目标用户

- 研究型交易者
- 盘中/盘后快速筛选热点的投资者
- 需要从新闻到题材再到股票形成闭环判断的用户

### 1.3 为什么现在前置

当前后端已经具备稳定的数据基础：

- `news_raw / news_event / event_theme_map`
- `theme_detail_snapshot / theme_history_event / theme_tree_relation / theme_stock_map`
- `/themes`、`/themes/rank`、`/themes/{subject_key}`、`/history`、`/children`、`/stocks`

因此现在最适合前置的是“认知展示层”，不是复杂行情终端。

同时需要明确边界：

- 当前前置版是 `REST first`
- 不承担实时推送能力
- 不直接承担复盘生成逻辑
- 不替代未来第三阶段的 `BFF / API Gateway`

> 2026-03-31 进一步修订：
> 情报台实时刷新已明确为下一步前置实现方向，但技术方案收敛为：
> `SSE + /api/intel/feed 轮询兜底`
> 而不是第一步直接建设完整 WebSocket 推送层。

## 二、产品定位

### 2.1 核心页面

新增一级页面：

- `/intel`

页面定位：

> 用一个高密度、低噪音的情报流，把“当天市场发生了什么、这些事件对应什么题材、哪些股票应该关注”直接呈现出来。

### 2.2 页面目标

回答 4 个问题：

1. 今天发生了哪些重要新闻事件？
2. 这些事件命中了哪些题材？
3. 今天有哪些新题材或新方向值得关注？
4. 对应应该看哪些股票？

---

## 三、参考久赢恒丰页面后的设计判断

### 3.1 截图分析结论

参考 `Web_UI` 截图后，页面设计应保留以下特征：

- 高密度信息布局
- 表格/树状结构优先于大卡片
- 涨跌幅和强弱状态直接用颜色编码
- 题材、子题材、股票三层关系一屏可读
- 事件和逻辑解释要靠近股票与题材，不应散落在多个页面

### 3.2 不建议的方向

- 不建议第一版就做成偏空洞的大卡片式 Dashboard
- 不建议先做重图表页而忽略情报流
- 不建议前端自己拼复杂逻辑，排序和权重应由后端给出

## 四、页面结构设计

### 4.1 页面整体布局

采用两栏半结构：

```text
┌──────────────────────────────────────────────────────┐
│ 顶部筛选栏                                           │
├───────────────────────────────┬──────────────────────┤
│ 左侧：情报主列表               │ 右侧：详情抽屉/侧栏   │
│ - 新闻事件                     │ - AI摘要             │
│ - 题材异动                     │ - 原始新闻           │
│ - 新题材候选                   │ - 题材树             │
│                                │ - 股票池/龙头        │
└───────────────────────────────┴──────────────────────┘
```

### 4.2 顶部筛选栏

字段：

- 日期选择
- 时段筛选：`盘前 / 盘中 / 盘后 / 全部`
- 类型筛选：`全部 / 新闻事件 / 题材异动 / 新题材`
- 题材搜索
- 股票搜索
- 置信度筛选

### 4.3 主列表区

列表项按时间倒序展示，每项为一个 `IntelFeedItemCard`。

每项展示：

- 时间
- 标题
- AI 摘要
- 类型标签
- 命中题材标签
- 重点股票标签
- 来源
- 影响分 / 置信度

### 4.4 右侧详情区

点击列表项后展开：

- 原始新闻/原始描述
- AI 因果链
- 命中题材详情
- 题材子树
- 题材股票池
- 龙头增强股票

## 五、信息类型设计

### 5.1 情报类型

第一版支持 3 类：

1. `event`
- 当天结构化新闻事件
- 来源：`news_raw + news_event + event_theme_map`

2. `theme_move`
- 题材异动、榜单变化、历史驱动
- 来源：`subject_rank_daily + theme_history_event`

3. `new_theme`
- 新题材候选 / 人工复核题材 / 新增久赢题材节点
- 来源：
  - `publish_clustering / human_review`
  - `subject_node_staging diff`

### 5.2 列表项数据结构

```ts
interface IntelFeedItem {
  item_id: string
  item_type: 'event' | 'theme_move' | 'new_theme'
  occurred_at: string
  title: string
  summary: string
  theme_subject_keys: string[]
  theme_names: string[]
  stock_ids: string[]
  stock_names: string[]
  confidence?: number
  impact_score?: number
  source_type: string
}
```

### 5.3 详情抽屉数据结构

```ts
interface IntelFeedDetail {
  item: IntelFeedItem
  raw_text?: string
  ai_reasoning?: string
  evidence_set?: Record<string, unknown>
  theme_detail?: ThemeDetail
  children?: ThemeChild[]
  stocks?: ThemeStock[]
}
```

## 六、后端接口设计建议

### 6.1 新增聚合接口

建议新增：

- `GET /intel/feed`

说明：

- 这是前置阶段的直接聚合接口
- 后续第三阶段落地 `intel_service + frontend_bff` 后，应将其迁移或代理到统一产品出口
- 前端页面不应继续无限扩张对底层领域接口的直接依赖

查询参数：

- `date`
- `session`
- `type`
- `subject_key`
- `stock_id`
- `limit`

返回：

```json
{
  "items": [],
  "count": 0,
  "date": "2026-03-31",
  "type": "all"
}
```

### 6.2 详情接口建议

可继续复用现有：

- `GET /themes/{subject_key}`
- `GET /themes/{subject_key}/history`
- `GET /themes/{subject_key}/children`
- `GET /themes/{subject_key}/stocks`
- `GET /stocks/{stock_id}/themes`

但建议作为过渡方案使用。

长期口径应收敛为：

- `GET /api/intel/feed`
- `GET /api/intel/{item_id}`
- `GET /api/theme-workspace/{subject_key}`
- `GET /api/stock-workspace/{stock_id}`

也就是由 `frontend_bff` 统一封装页面所需数据。

### 6.3 股票接口口径

当前股票映射已分层：

- 默认 `mapping_scope=pool`
- 显式 `mapping_scope=leader_overlay`
- 或 `mapping_scope=all`

所以前端题材详情页建议：

- 默认显示完整股票池
- 提供“叠加龙头”开关

## 七、前端技术实现建议

### 7.1 技术栈

- React 18
- TypeScript
- Vite
- Tailwind CSS
- Zustand

### 7.2 工程建议

建议新建独立前端目录：

- `frontend/`

避免把前端页面直接混入当前 Python 服务目录。

### 7.3 与第三阶段的兼容原则

前端前置实现必须遵守以下约束：

- 页面主键统一使用 `subject_key`
- 股票映射默认只读主股票池，`leader overlay` 作为可选增强
- 页面排序、权重、聚合逻辑优先由后端输出，不由前端自行拼接
- 当前可以直连 `theme_service`，但后续必须可平滑迁移到 `frontend_bff`

### 7.3 页面与组件拆分

建议组件树：

- `IntelPage`
  - `IntelToolbar`
  - `IntelFeedList`
    - `IntelFeedItemCard`
  - `IntelDetailDrawer`
    - `IntelSummaryPanel`
    - `ThemeMiniTree`
    - `ThemeStockPanel`
    - `RawNewsPanel`

## 九、当前阶段建议

当前最合理的前置范围是：

- 先做 `/intel` 情报列表页
- 题材详情页以右侧抽屉形式接入
- 暂不做复杂图表和分时

原因：

- 后端认知对象已经稳定
- 行情强化层还可以后置
- 情报流最能立刻体现项目价值

## 十、验收目标

第一版验收以“看得见、能筛选、能联动”为主：

1. 能看到当天情报列表
2. 能区分新闻事件、题材异动、新题材
3. 能点击进入题材详情
4. 能看到题材股票池
5. 能看到龙头增强股票
6. 能把“新闻 -> 题材 -> 股票”串起来
