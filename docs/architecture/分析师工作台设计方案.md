## 0. 架构升级总览

### 0.1 从四层到五层

```
v1.0 架构（已废弃）                  v2.0 架构（当前）
───────────────                    ───────────────
Market Data                        L0 — Raw Data
    │                                  │
    ▼                                  ▼
M8 World State                     L1 — Market World（市场事实）
    │                                  │
    ▼                                  ▼
M8.5 Analyst Cognition             L2 — Market Attention（今天到底该看什么）
    │                                  │
    ▼                                  ▼
M9 Intelligence                    L3 — Analyst Cognition（如何理解）
    │                                  │
    ▼                                  ▼
Strategy                           L4 — Trading Decision（如何交易）
```

**关键变化：增加 L2 Attention Layer。**

分析师一天真正花时间的不是"分析"，而是"决定今天到底看什么"。

如果没有 Attention 过滤，AI 每天面对 2000 条新闻、500 个板块、6000 只股票，没有模型能处理。必须先决定"哪些值得投入认知资源"。

### 0.2 M8.5 六引擎架构

```
M8.5 Analyst Cockpit（分析师驾驶舱）
│
├── ■ Attention Engine       — 今天该看什么
├── ■ Cognition Engine       — 如何理解市场
├── ■ Narrative Engine       — 为什么今天会这样
├── ■ Causal Engine          — 市场因果图
├── ■ Leader Evolution Engine — 龙头生命周期
└── ■ Playbook Engine        — 交易剧本
```

```

## Part I — 六引擎设计

### 1. Attention Engine（关注引擎）

**回答：今天到底该看什么？**

```python
@dataclass(frozen=True, slots=True)
class MarketAttentionState:
    """每日注意力分配状态。"""
    
    trade_date: date
    
    # ── 题材关注 ──
    high_attention_subjects: tuple["SubjectAttention", ...]    # ★★★★★ / ★★★★☆
    watch_subjects: tuple["SubjectAttention", ...]             # ★★★☆☆
    ignore_subjects: tuple[str, ...]                           # ★★☆☆☆ / ★☆☆☆☆
    
    # ── 个股关注 ──
    watch_stocks: tuple["StockAttention", ...]
    
    # ── 事件关注 ──
    watch_events: tuple["EventAttention", ...]
    
    # ── 外部锚定 ──
    external_anchors: tuple["ExternalAnchor", ...]
    
    # ── 全局注意力预算 ──
    total_attention_budget: int  # 总认知资源份额（默认 100）
    allocated_attention: int     # 已分配份额


@dataclass(frozen=True, slots=True)
class SubjectAttention:
    subject_id: str
    attention_score: int     # 0-100
    level: str               # CRITICAL / HIGH / MEDIUM / LOW / IGNORE
    
    # 共振信号（分数来源）
    event_signals: int       # 事件刺激强度
    price_signals: int       # 价格信号强度（龙头涨停/异动）
    capital_signals: int     # 资金信号强度
    external_signals: int    # 外部锚定信号（韩国/美股映射）
    sentiment_signals: int   # 市场情绪信号
    
    reasons: tuple[str, ...]  # 为什么被关注（最多 3 条）


@dataclass(frozen=True, slots=True)
class StockAttention:
    stock_id: str
    attention_score: int
    reason: str               # 涨停 / 异动 / 龙头 / 事件映射 / 资金异常
    event_link: str | None    # 关联事件
```

**Attention Engine 的计算规则（Phase 1 确定性版本）：**

```
attention_score = 
    event_signals × 0.25 +
    price_signals × 0.30 +
    capital_signals × 0.25 +
    external_signals × 0.10 +
    sentiment_signals × 0.10

>= 80 → CRITICAL（★★★★★）
60-79 → HIGH（★★★★☆）
40-59 → MEDIUM（★★★☆☆）
20-39 → LOW（★★☆☆☆）
< 20  → IGNORE（★☆☆☆☆）
```

### 3. Narrative Engine（叙事引擎）

**回答：为什么今天市场会这样？**

```python
@dataclass(frozen=True, slots=True)
class MarketNarrative:
    """每日市场叙事 — 不是罗列事实，而是因果故事。"""
    
    trade_date: date
    
    main_story: str             # 主线故事（今天市场的核心叙事）
    main_story_chain: tuple[str, ...]  # 因果链，每条 1-2 句
    
    secondary_stories: tuple[str, ...]  # 支线故事
    failed_stories: tuple[str, ...]     # 预期但未发生的故事
    unexpected_stories: tuple[str, ...] # 意料之外的故事
    
    narrative_graph: "NarrativeGraph"   # 叙事图


@dataclass(frozen=True, slots=True)
class NarrativeGraph:
    """叙事因果图。"""
    nodes: tuple["NarrativeNode", ...]
    edges: tuple["NarrativeEdge", ...]


@dataclass(frozen=True, slots=True)
class NarrativeNode:
    node_id: str
    node_type: str              # event / theme / stock / index / sentiment / capital
    label: str                  # 简短描述
    evidence_refs: tuple[str, ...]


@dataclass(frozen=True, slots=True)
class NarrativeEdge:
    from_node: str
    to_node: str
    relation: str               # causes / boosts / weakens / replaces / inherits / rotates
    confidence: float
```

**叙事生成示例：**

### 4. Causal Engine（因果引擎）

**回答：事件如何传导到个股？**

```python
@dataclass(frozen=True, slots=True)
class MarketCausalGraph:
    """市场因果图 — 不是关键词匹配，是真正的因果推理。"""
    
    trade_date: date
    
    # 节点类型
    events: tuple["CausalEventNode", ...]
    themes: tuple["CausalThemeNode", ...]
    stocks: tuple["CausalStockNode", ...]
    indices: tuple["CausalIndexNode", ...]
    capital_flows: tuple["CausalCapitalNode", ...]
    sentiment: tuple["CausalSentimentNode", ...]
    
    # 边
    edges: tuple["CausalEdge", ...]


@dataclass(frozen=True, slots=True)
class CausalEdge:
    source_id: str
    target_id: str
    relation: str               # causes / boosts / weakens / replaces / inherits / rotates_to / rotates_from
    strength: float             # 0-1
    evidence: tuple[str, ...]   # 支撑证据
    time_lag: int               # 传导时滞（交易天数）


# 因果链示例：
# Meta capex ↑ → 算力出租 ↑ → AI需求 ↑ → 光模块 ↑ → CPO ↑ → 通信 ↑ → PCB ↑ → 铜缆 ↑ → 交换机 ↑ → 龙头确认
```

**Phase 1 确定性版本：**
- 使用预先定义的因果链模板（从分析师 PDF 提取）
- 每个交易日根据实际数据激活/停用边
- AI 不生成因果链，AI 只消费因果链做推理

### 6. Playbook Engine（交易剧本引擎）

**回答：现在是该买、该卖、还是该等？**

```python
@dataclass(frozen=True, slots=True)
class MarketPlaybook:
    """每个题材的交易剧本。"""
    
    subject_id: str
    trade_date: date
    
    # 剧本定义
    phase: str                  # 启动 / 发酵 / 高潮 / 分歧 / 修复 / 退潮
    current_step: int           # 当前在第几步
    total_steps: int            # 总步数
    completion_pct: float       # 当前阶段完成度 0-100
    
    # 策略
    strategy: str               # 只做低位补涨 / 等待分歧 / 做修复 / 追龙头 / 观望
    entry_condition: str        # 入场条件
    exit_condition: str         # 离场条件
    invalidation_condition: str # 剧本失效条件
    
    # 观察点
    tomorrow_watchpoints: tuple[str, ...]  # 明天要观察什么
    key_risk: str                           # 最大风险
    
    # 历史剧本
    previous_playbooks: tuple["PlaybookSnapshot", ...]


@dataclass(frozen=True, slots=True)
class PlaybookSnapshot:
    """剧本历史快照 — 用于复盘验证。"""
    trade_date: date
    phase: str
    strategy: str
    was_correct: bool | None     # None = 未验证
    actual_outcome: str | None
```

### 8. 六个协同面板

#### 面板 1：Attention Radar（关注雷达）

- **位置**：左上
- **内容**：AI 自动评分并排序的题材/龙头/事件列表
- **交互**：点击任意条目，Evidence Panel 自动展示证据
- **状态**：分析师可以调级（升/降星）、新增、忽略

#### 面板 2：Evidence Panel（证据面板）

- **位置**：中上
- **内容**：当前选中判断的所有证据，可按来源分组展开
- **来源**：新闻原文 / 涨停时间 / K线图 / 资金流向 / 板块扩散 / 外部映射
- **原则**：每一个认知判断都必须能展开到 1-3 条可验证的证据

#### 面板 3：Cognition Workspace（认知工作区）

- **位置**：中部（最大区域）
- **内容**：当前选中题材的完整 CognitionCard
- **交互**：每个字段三种状态颜色（灰/绿/黄/红），支持 AI 填充 + 分析师修改
- **保存**：每次保存自动记录 OverrideLog

#### 面板 4：Narrative Builder（叙事生成器）

- **位置**：左下
- **内容**：AI 自动生成的主线/支线/失败故事 + 因果链
- **交互**：分析师可调序、删除、补充因果边
- **输出**：最后成为复盘报告的核心骨架

#### 面板 5：Playbook Builder（交易剧本）

- **位置**：右下
- **内容**：每个重点题材的交易剧本（阶段/策略/失效条件/观察点）
- **交互**：AI 生成草稿 → 分析师确认关键判断
- **验证**：第二天 Review 面板自动对比实际

## Part IV — AI + 分析师协同流程（升级版）

### 10. 三层 Attention 预算

```
AI 认知预算分配（每日 100 单位）：

CRITICAL 题材（≥80 分）：每个分配 20-25 单位 → 深度分析（全量 CognitionCard）
HIGH 题材（60-79 分）：   每个分配 10-15 单位 → 标准分析（精简 CognitionCard）
MEDIUM 题材（40-59 分）： 每个分配 5 单位    → 摘要分析（仅关键字段）
LOW/IGNORE 题材（<40 分）：分配 0 单位       → 跳过
```

### 11. 六步每日闭环

```
Step 1: Attention → Radar 自动刷新
  - AI 扫描 2000 条新闻/500 板块/6000 股票
  - 自动评分 → 分配认知预算
  - 分析师可调级（2 分钟内完成）

Step 2: Evidence → 自动链接
  - 对高关注题材，AI 自动拉取证据
  - 新闻（原文）、涨停时间、K线、资金流向、外部映射
  - 每个判断可展开查看证据

Step 3: Cognition → 协同填写
  - AI 自动填充 CognitionCard（灰色字体）
  - 分析师逐个审核关键字段
  - 每次保存 = OverrideLog 记录

Step 4: Narrative → 生成故事
  - AI 消费 Cognition + CausalGraph → 生成叙事
  - 主故事 + 因果链 + 支线 + 意外
  - 分析师调整叙事逻辑

Step 5: Playbook → 制定剧本
  - AI 根据当前阶段自动推荐策略
  - 分析师确认入场/离场/失效条件
  - 生成明天观察清单

Step 6: Review → 验证学习
  - 对比昨日预测 vs 今日实际
  - 记录 OverrideLog
  - 更新 AI 准确率
```

## Part VII — Workbench Review Workflow（Phase 4.5 已实现）

### 14.5 Phase 4.5.5 — Analyst Workbench First（职责归位）

Phase 4.5.5 不新增全自动编排层。当前阶段的目标是收紧已有能力的边界，让分析师工作台成为复盘生产入口，当日复盘成为正式报告展示入口。

目标链路：

```
市场数据
   │
   ▼
PostMarket Derived Data
   │
   ▼
Analyst Workbench
   ├── 启动分析：生成动态复盘数据
   ├── AI Draft：生成情绪、图表、认知卡片、叙事、剧本草稿
   ├── Analyst Review：人工修正、校准、OverrideLog
   └── Approve：生成 immutable Approved Snapshot
   │
   ▼
compose-from-workbench
   │
   ▼
DailyReviewV2 / Notion / UI
```

职责裁决：

| 模块 | 负责 | 不负责 |
|---|---|---|
| Analyst Workbench | 动态复盘数据生产、AI Draft、人工 Review、Approved Snapshot | 自动发布、自动交易决策、M9 Learning |
| DailyReview | 消费 Approved Snapshot、报告编译、展示、发布 | 生产动态数据、绕过审核读取 draft |
| M8 Stable Core | Evidence / Context / Cognition / Thesis 的只读编排 | 被 DailyReviewV2 反向污染 |

关键约束：

1. `POST /api/v1/analyst-workbench/{date}/generate` 通过薄 application service 接管原 DailyReview 侧的 derived data 生成入口。
2. `approve` 必须合并 `AIDraft + tmp/analyst_workspace/{date}.json + OverrideLog`，Approved Snapshot 才能代表人工确认结果。
3. `POST /api/v2/daily-review-v2/compose-from-workbench` 是正式报告唯一入口，只允许读取 approved `snapshot.json`。
4. `GET /api/v2/daily-review-v2` 可继续作为 preview/read 页面，允许展示 draft，但不得作为正式报告发布真源。
5. 前端“生成复盘报告”使用 `mode=read_model_only`，不得默认 `force=true` 触发事实重建。

明确暂缓：

- `AnalystReviewOrchestrator`
- Workflow Engine / Event Bus
- 自动收盘触发复盘
- M9 Learning Loop
- 新增数据库持久化表

### 15. 工作台状态机

工作台从"展示页面"升级为"每日复盘生产线"。每个交易日有一个明确的 WorkbenchSession 状态。

```
NOT_STARTED ──→ GENERATING ──→ DRAFT_READY ──→ IN_REVIEW ──→ APPROVED ──→ PUBLISHED
     ↑               │              │               │             │
     └── FAILED ←────┴──────────────┴───────────────┴─────────────┘
                                                              STALE（数据更新后过期）
```

**合法状态转移表：**

```
NOT_STARTED → GENERATING / FAILED
GENERATING  → DRAFT_READY / FAILED
DRAFT_READY → IN_REVIEW / GENERATING / FAILED
IN_REVIEW   → DRAFT_READY / APPROVED / FAILED
APPROVED    → PUBLISHED / STALE
PUBLISHED   → STALE
STALE       → GENERATING
FAILED      → GENERATING
```

**关键守卫：**
- APPROVED 后不可直接修改 draft（必须先 STALE）
- PUBLISHED 后拒绝 save-review
- 非法状态跳转抛出 ValueError
- GET session 只读，不触发隐式 AI 生成

### 16. 数据模型

**WorkbenchSession** (`tmp/analyst_workbench/{date}/session.json`):
```
trade_date, status, draft_version, snapshot_version,
created_at, updated_at, generated_at, reviewed_at,
approved_at, published_at, approved_by, error_message
generation_steps
+ can_generate, can_review, can_approve, can_publish 属性
```

**AIDraft** (`tmp/analyst_workbench/{date}/drafts/draft_vN.json`):
```
trade_date, draft_version, supersedes_version,
attention_state, cognition_cards, narrative, playbook,
generated_by, generated_at, source_quality, missing_fields
```

**ReviewSnapshot** (`tmp/analyst_workbench/{date}/snapshot.json`):
```
trade_date, snapshot_version, based_on_draft_version,
approved, approved_at, approved_by,
approval_mode, source_mode, snapshot_hash,
attention_state, cognition_cards, narrative, playbook,
override_summary
```

`approval_mode` 固定取值：

```
preview / review / analyst_approved / published
```

正式报告只接受：

```
approved=true
approval_mode=analyst_approved 或 session=PUBLISHED
source_mode=analyst_workbench
composition_mode=formal
snapshot_hash 非空
```

**OverrideLog** (`tmp/analyst_workbench/{date}/overrides.jsonl`):
- JSONL 追加格式，每次 review 保存追加一行
- AI Draft 和 Analyst Override 必须双轨保存，不能只保留 final 值：

```json
{
  "field": "main_theme",
  "ai_value": "机器人",
  "analyst_value": "PCB",
  "final_value": "PCB",
  "override": true,
  "reason": "资金切换"
}
```

### 17. API 端点

| Method | Route | Purpose |
|--------|-------|---------|
| GET | `/api/v1/analyst-workbench/{date}/session` | 返回 session 状态（不触发生成） |
| POST | `/api/v1/analyst-workbench/{date}/generate` | 触发 AI draft 生成（Phase 1 同步） |
| POST | `/api/v1/analyst-workbench/{date}/save-review` | 保存分析师审查 + overrides |
| POST | `/api/v1/analyst-workbench/{date}/approve` | 创建 immutable ReviewSnapshot，状态→APPROVED |
| POST | `/api/v1/analyst-workbench/{date}/publish` | 发布（需 approved snapshot），状态→PUBLISHED |

**旧接口兼容：** `/api/v1/analyst-workspace/{date}` 优先读取 snapshot（approved）或 draft（DRAFT_READY），不存在时返回 NOT_STARTED + can_generate=true。不再隐式生成。

### 18. AI Draft Generator CLI

```bash
PYTHONPATH=. python3 scripts/generate_analyst_workbench.py --date 2026-07-09
```

行为：
1. 加载/创建 WorkbenchSession → 转为 GENERATING
2. 从 chart JSON + emotion JSON 构造 AIDraft
3. 写入 draft_vN.json + 更新 session 为 DRAFT_READY
4. 如果已有 approved snapshot，拒绝覆盖（需先标记 STALE）

Phase 4.5.5 后，HTTP 入口 `/api/v1/analyst-workbench/{date}/generate` 只调用 `AnalystWorkbenchGenerateService`。该 service 在调用 CLI 前完成：

```
AnalystWorkbenchGenerateService.generate(date)
  ├── PostMarketDerivedDataGenerateUseCase.execute(force=True)
  ├── chart JSON
  ├── emotion JSON
  └── generate_analyst_workbench.py
```

CLI 本身仍保持“从已生成文件构造 AI Draft”的职责，不直接承担 derived data 编排。该 service 不是 Orchestrator：不维护长期状态、不订阅事件、不做自动触发，只做单次 HTTP 请求内的同步能力组合。
