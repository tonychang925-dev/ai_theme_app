## 0. 定位声明

M8.5 不是 M9 的前置任务，也不是 Phase 1.5 的扩展。

它的定位是：

> **在 World State（M8）之上，建立 Analyst Cognition State（分析师认知状态），通过 AI + 分析师协同维护，形成持续演化的市场认知地图。**

Phase 1.6–1.8 证明了：
- Policy 不是瓶颈
- World Model 的真实性是瓶颈
- 真实世界建模需要的不只是数据，而是**分析师如何理解这些数据的认知模式**

本设计文档定义 M8.5 的完整架构，包括领域模型、数据模型、前端设计、协同流程和分阶段实施计划。

## Part I — Core Concept

### 1. Market Cognition Map（市场认知地图）

分析师真正做的工作不是"分析题材"，而是在维护一张市场认知地图。

```
市场数据
    │
    ▼
分析师不断维护自己的市场认知
    │
    ▼
每天更新认知地图
    │
    ▼
最后才输出复盘报告
```

**复盘只是结果。真正有价值的是中间那张不断变化的 Market Cognition Map。**

### 2. Theme Cognition（题材认知）

当前系统有 `MarketSubject`（聚合根），但它只包含身份信息（subject_id, name, type）。

分析师实际维护的是一个完整的**题材认知画像**：

```
通信 / CPO
───────────────────────────────
战略层：当前属于趋势 / 轮动 / 超跌 / 修复 / 高潮 / 退潮
交易层：炒作风格 → 机构 / 游资 / 量化 / 机游合力 / 趋势
结构层：龙头 / 中军 / 跟风 / 补涨 / 穿越 / 高低切
行为层：昨天怎么看 → 今天怎么看 → 明天怎么看
情绪层：交易者心态 / 指数共振 / 市场认可度
操作层：继续观察 / 左侧 / 右侧 / 等待一致 / 等待分歧 / 等待修复
```

### 3. Theme Evolution Tree（题材生命周期树）

分析师维护的不只是"机器人"这个题材，而是：

```
机器人
  ├── Stage 1（趋势中军）：埃斯顿
  ├── Stage 2（减速器）：兆威机电、雷赛智能
  ├── Stage 3（传感器）：日盈电子
  ├── Stage 4（设备）：XXXX
  ├── Stage 5（材料）：XXXX
  └── Stage 6（补涨）：XXXX
```

每个 Stage 有自己的 Leader、Followers、Failed、Abandoned。
这棵树随着时间演化，每天更新。

## Part II — Domain Model

### 4. ThemeCognition（核心新增对象）

```python
@dataclass(frozen=True, slots=True)
class ThemeCognition:
    """每个题材每天一份认知画像 — 对应分析师 PDF 的每一行。"""
    
    cognition_id: str
    subject_id: str              # -> MarketSubject
    trade_date: date
    
    # ── 战略层 ──
    market_phase: str            # 趋势 / 轮动 / 超跌 / 修复 / 高潮 / 退潮
    phase_confidence: float      # 0-1
    
    # ── 交易层 ──
    trading_style: str           # 机构 / 游资 / 量化 / 机游合力 / 趋势
    style_evidence: tuple[str, ...]
    
    # ── 结构层 ──
    leaders: tuple["LeaderRole", ...]
    potential_leaders: tuple["LeaderRole", ...]
    mid_cap: tuple[str, ...]     # 中军
    followers: tuple[str, ...]   # 跟风
    supplement: tuple[str, ...]  # 补涨
    cross_over: tuple[str, ...]  # 穿越
    
    # ── 行为层 ──
    yesterday_view: str          # 昨日思路
    today_actual: str            # 今日实际
    expectation_delta: str       # 预期复核（AI预测 vs 实际）
    tomorrow_view: str           # 隔日思考
    
    # ── 情绪层 ──
    trader_sentiment: str        # 交易者心态
    index_resonance: str         # 指数共振
    market_acceptance: float     # 市场认可度 0-1
    money_making_effect: str     # 赚钱效应
    money_losing_effect: str     # 亏钱效应
    
    # ── 操作层 ──
    action_advice: str           # 继续观察 / 左侧 / 右侧 / 等待一致 / ...
    repair_probability: float    # 修复概率 0-1
    fade_probability: float      # 退潮概率 0-1
    
    # ── 证据 ──
    evidence_refs: tuple[str, ...]
    ai_generated: bool           # 是否由 AI 生成
    analyst_reviewed: bool       # 是否经分析师审核
    analyst_modified: bool       # 分析师是否做了修改
    
    # ── M8 桥接 ──
    cycle_node: str | None       # -> CycleNode.name（与 M8 World State 对齐）
```


### 5. LeaderRole（龙头角色）


## Part IV — Frontend Design

### 11. 页面总体结构

```
Analyst Workspace（分析师工作台）
├── 01 导航栏         — 日期选择 + 工作区状态 + 保存/发布
```

## Part V — AI + 分析师协同流程

### 18. 三阶段演进

```
阶段 1：AI 辅助，分析师主导
  AI 自动生成候选题材、股票池、事件归因草稿
  分析师独立审核、修改、补充每一个字段
  系统记录每一次 override
  目标：建立可信的标注基线

阶段 2：AI 半主导，分析师纠偏
  AI 生成完整 Theme Cognition Card
  分析师只修正关键字段：
    - 龙头确认
    - 阶段研判
    - 隔日思考
    - 操作建议
  其他字段以 AI 为主
  目标：AI 准确率达到 70%+

阶段 3：AI 主导，分析师抽检
  AI 自动完成盘前/盘中/盘后全部认知
  分析师只审核异常题材与关键判断
  系统自动标记高不确定性输入
  目标：AI 准确率达到 85%+
```

### 19. 每日协同流程

```
盘前（08:00-09:00）
  AI 自动生成：
    - 今日重点题材推荐
    - 昨日预期复核结果
    - 盘前事件刺激列表
```

## Part VIII — 数据资产价值

### 24. OverrideLog 的战略意义

`analyst_override_log` 是未来最重要的数据资产：

```
每天：
  分析师修改 AI 判断 × 20-30 条

一个月：
  600-900 条标注数据

一年：
  7200-10800 条高质量纠偏样本

用途：
  1. 训练 AI 从"辅助"走向"主导"
  2. 发现 AI 系统性偏差（总是高估修复概率？总是遗漏某种龙头？）
  3. 建立分析师判断模型（什么情况下分析师会修改 AI？）
  4. 度量 AI 准确率（Override rate = 1 - 准确率）
```

### 25. 认知数据闭环

```
AI 生成认知
    │
    ▼
分析师审核/纠偏
    │
    ▼
OverrideLog 记录差异
    │
    ▼
训练数据积累
    │
    ▼
AI 模型升级
    │
    ▼
AI 准确率提升
    │
    ▼
减少分析师工作量
    │
    ▼
循环
```

## Part IX — 最终定位

M8.5 Analyst Workspace 不是普通前端功能。

它是：

1. **市场认知标注系统** — 持续沉淀分析师对市场的主观判断
2. **AI 训练数据工厂** — 每个 override 都是未来 AI 升级的燃料
3. **从辅助到主导的桥** — Override rate 从高到低的过程，就是 AI 从辅助走向主导的过程

当一个系统能记录：
- 分析师认为谁是龙头，为什么是龙头
- 哪些判断后来被验证，哪些被证伪
- AI 的判断在什么情况下被分析师推翻
- 每个题材的完整生命周期轨迹

它就不再是一个"分析工具"，而是一个**持续进化的市场认知引擎**。
