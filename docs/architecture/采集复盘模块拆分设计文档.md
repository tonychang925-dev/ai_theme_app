## 一、背景与目标

### 1.1 现状问题

当前"日采集控制台"（RealtimeCollectorPage）混合了采集和复盘两种职责，导致以下问题：

1. **职责混乱**：同一个控制台既执行基础数据采集（JYHF/K线/龙虎榜/异动），又执行复盘生成（recap_snapshot），用户无法区分
2. **链路不可靠**：`strong_stock_watch` 任务是假成功（代码返回 success 但实际不执行）；`recap_snapshot` fast模式被混入producer步骤导致每天换一个地方炸
3. **复盘数据缺失**：DailyReview 依赖的 `theme_cycle_judgement_v2`、`dragon_tiger_object`、`money_flow_enhanced`、`strong_stock_watch_history` 四张核心表经常为空，复盘报告大量栏目无数据
4. **前端展示违规**：RecapPage 出现新的 `DailyReviewTable`（"主线与支线（结构化）"），不符合5/22已验收样式

### 1.2 拆分目标

```
旧：日采集控制台（混合） → 采集 + 复盘混在一起
新：采集模块（独立） + 复盘模块（独立） → 职责清晰、合约冻结
```

## 二、模块一：采集模块（日采集控制台）

### 2.1 定位

**只做基础数据采集，不做任何复盘功能。**

采集模块负责从外部数据源拉取原始数据，写入底层数据表。不涉及任何复盘报告生成、不触发 DailyReview、不运行 cycle/identity/mainline 等派生逻辑。

### 2.2 职责范围

| 任务 | 功能 | 写入目标表 |
|------|------|-----------|
| 股票快照 | JYHF 题材列表/节点/详情/股票日快照同步 | `subject_detail`, `subject_stock_daily_snapshot` |
| Tushare日K线 | 日K线 + 盘前竞价采集 | `stock_daily_bar`, 竞价相关表 |
| 龙虎榜 | 龙虎榜数据采集 | `dragon_tiger_object` |
| 异动股票 | 异动信号检测 | `stock_abnormal_signal` |
| 龙头候选LLM | 龙头候选LLM队列/研判/调用/候选 | leader_llm 相关表 |

### 2.3 明确禁止

采集模块**禁止**执行以下操作：

1. 禁止执行 `recap.prerequisites`（evidence → cycle → identity → mainline）
2. 禁止执行 `recap.snapshot`（复盘快照生成）
3. 禁止执行 `BuildPostMarketRecapJob`
4. 禁止执行 `money_flow_enhanced` 脚本
5. 禁止执行 `stock_kline_judgements`
6. 禁止调用 `BuildStrongStockTrackingUseCase`（Layer C）
7. 禁止写入 `post_market_recap_snapshot`

### 2.4 页面入口

**前端页面**：`/collection`（RealtimeCollectorPage）  
**后端API**：`POST /api/v1/collection/start`（SPS端口8090）  
**代理API**：`POST /api/v2/collection/start`（web_app端口8000）

### 2.5 状态展示

控制台显示每个采集任务的状态：

| 任务 key | 显示名称 | 状态 |
|----------|---------|------|
| `jyhf` | 股票快照 | pending/running/success/failed |
| `tushare_kline` | Tushare日K线 | pending/running/success/failed |
| `dragon_tiger` | 龙虎榜 | pending/running/success/failed |
| `abnormal_signal` | 异动股票数据 | pending/running/success/failed |
| `leader_llm` | 龙头候选LLM裁决 | pending/running/success/failed |

### 2.6 移除项

以下任务从采集控制台**永久移除**：

- ~~`strong_stock_watch`（强势股跟踪池）~~ — 已废弃，假成功误导用户，Layer C 由复盘模块负责
- ~~`recap_snapshot`（盘后复盘快照）~~ — 移至复盘模块

### 2.7 采集模块合约冻结

```
采集任务 → 写入底层数据表 → 完成
         ↓
    不触发任何复盘逻辑
    不写入 post_market_recap_snapshot
    不运行 cycle/identity/mainline
```

## 三、模块二：复盘模块（当日复盘页面）

### 3.1 定位

复盘模块分为两大阶段：

1. **阶段一：每日动态复盘数据生成** — 运行派生producer，将底层数据汇总为复盘报告
2. **阶段二：复盘报告展示** — 从快照读取结构化DailyReview，按5/22样式渲染

### 3.2 阶段一：每日动态复盘数据生成

#### 3.2.1 执行模式

| 模式 | 说明 | 执行内容 | 耗时 |
|------|------|---------|------|
| **快速生成**（默认） | Read-model only，只读取已生成的派生数据 | `BuildDailyReviewReadModelJob` | 10-30秒 |
| **全量重建** | 重新跑完整派生链 + 复盘生成 | evidence→cycle→identity→mainline→LayerC→money_flow→recap | 5-10分钟 |

#### 3.2.2 快速生成（默认模式）

**不运行任何producer**，只读取已有对象表生成DailyReview。

执行链：
```
读取已有对象表
  ├─ theme_cycle_judgement_v2    → cycles
  ├─ theme_mainline_identity_registry → identity
  ├─ money_flow_enhanced         → money_flow
  ├─ dragon_tiger_object         → dragon_tiger
  ├─ subject_stock_daily_snapshot → stock_facts
  └─ strong_stock_watch_history  → strong_watch
      ↓
BuildDailyReviewReadModelJob
      ↓
写入 post_market_recap_snapshot
```

**前置条件**：底层数据表必须有当日数据（由全量重建或之前成功运行产生）。

**快速生成日志验收标准**：
```
日志必须出现：
  DailyReview read-model only
  BuildDailyReviewReadModelJob 开始执行
  BuildDailyReviewReadModelJob 完成
  recap status=ok

日志不得出现：
  BuildThemeCycleEvidenceDailyJob
  BuildCycleJudgementJob
  BuildIdentityJob
  BuildMainlineStateJob
  BuildStrongStockTrackingUseCase
  stock.kline_judgements
  money_flow_enhanced
```

#### 3.2.3 全量重建（force_rebuild_truth_source=true）

运行完整派生链 + 复盘生成。

执行链：
```
Step 1: stock.kline_judgements      → K线位置与形态判断
Step 2: recap.prerequisites          → evidence → cycle → identity → mainline
Step 3: market_environment_daily     → 市场环境检查
Step 4: theme_capital_flow_daily     → 题材资金流检查
Step 5: money_flow_enhanced          → 资金行为增强
Step 6: Layer C (strong_stock_tracking) → 强势股跟踪池
Step 7: abnormal_signal              → 异动信号检测
Step 8: BuildDailyReviewReadModelJob → 复盘报告生成
      ↓
写入 post_market_recap_snapshot
```

#### 3.2.4 API端点

| 方法 | 端点 | 说明 |
|------|------|------|
| `POST` | `/api/v1/daily_review/generate` | SPS: 生成每日复盘快照 |
| `POST` | `/api/v2/daily-review/generate` | web_app代理 |
| `GET` | `/api/v1/daily_review?trade_date=` | SPS: 读取每日复盘 |
| `GET` | `/api/v2/daily-review?date=` | web_app代理 → 前端消费 |

**请求体**（generate）：
```json
{
  "date": "2026-05-26",
  "mode": "read_model_only"
}
```

- `read_model_only`（默认）：快速生成，10-30秒
- `full_truth_rebuild`：全量重建，5-10分钟

#### 3.2.5 阶段一页面入口

**前端页面**：`/recap`（RecapPage）中的"生成复盘报告"按钮  
**按钮拆分**：

| 按钮 | 模式 | 说明 |
|------|------|------|
| **快速生成复盘报告** | `read_model_only` | 默认按钮，读取已有数据，10-30秒 |
| **全量重建盘后数据** | `full_truth_rebuild` | 危险操作，仅管理端，5-10分钟 |

### 3.3 阶段二：复盘报告展示

#### 3.3.1 数据源

```
GET /api/v2/daily-review?date=YYYY-MM-DD
  → DailyReview {
      review_date,
      market_summary,
      theme_reviews[],
      capital_reviews[],
      trading_principle,
      created_at
    }
```

**主数据源**：`dailyReview.theme_reviews`  
**旧 sections**：仅作 fallback 和 ReportPreviewPanel 文本预览  
**禁止**：前端重新解析中文报告文本来生成核心业务表格

#### 3.3.2 展示样式（强制5/22验收样式）

复盘报告展示**必须复用5/22已验收样式**，使用以下组件和className：

```
workspace-card
recap-table-stack
recap-table-card
recap-table-wrap
recap-table
metric-label section-title
tag / tag-button
```

**禁止**新增不符合5/22样式的新表格组件（如当前的 `DailyReviewTable`（"主线与支线（结构化）"））。

#### 3.3.3 栏目映射

| 栏目 | 数据来源 | 渲染组件 |
|------|---------|---------|
| 主线与支线 | `dailyReview.theme_reviews` | ThemeSummaryRow（5/22样式） |
| 主线资金流入前10 | `report_context.theme_capital_flow` / `money_flow` | ThemeCapitalFlowRow（5/22样式） |
| 强势股分层 | `report_context.stock_facts` | StrongStockRow（5/22样式） |
| 龙虎榜 | `dailyReview.capital_reviews` | DragonTigerRow（5/22样式） |

**缺失数据处理**：
- 栏目数据为空时，显示"暂无数据"（而非空白）
- `diagnostics.missing_sections` 记录缺失的数据源
- 页面不因部分数据缺失而崩溃或白屏

## 四、核心数据表依赖

### 4.1 数据表全景

| 表名 | 由谁填充 | 由谁读取 | 用途 |
|------|---------|---------|------|
| `subject_stock_daily_snapshot` | JYHF采集 | report_context | 股票日快照/市场统计 |
| `theme_cycle_judgement_v2` | `recap.prerequisites`(force) | report_context.cycles | 题材周期/主线状态 |
| `theme_mainline_identity_registry` | `recap.prerequisites`(force) | report_context | 主线身份注册 |
| `dragon_tiger_object` | 龙虎榜采集 | report_context.dragon_tiger | 龙虎榜数据 |
| `money_flow_enhanced` | `money_flow_enhanced` 脚本(force) | report_context.money_flow | 资金流增强 |
| `strong_stock_watch_history` | Layer C (force) | report_context | 强势股跟踪历史 |
| `strong_stock_watch_pool` | Layer C (force) | report_context | 强势股池 |
| `post_market_recap_snapshot` | BuildDailyReviewReadModelJob | RecapPage API | 复盘快照 |

### 4.2 数据依赖链

```
采集阶段（采集模块）
  subject_stock_daily_snapshot  ← JYHF/K线/竞价
  dragon_tiger_object           ← 龙虎榜采集
  stock_abnormal_signal         ← 异动检测
  leader_llm_*                  ← LLM裁决

        ↓ (全量重建时)

派生阶段（复盘模块-阶段一 full_truth_rebuild）
  theme_cycle_judgement_v2          ← BuildCycleJudgementJob
  theme_mainline_identity_registry  ← BuildIdentityJob
  mainline_state_daily              ← BuildMainlineStateJob
  money_flow_enhanced               ← build_money_flow_enhanced.py
  strong_stock_watch_history        ← BuildStrongStockTrackingUseCase
  strong_stock_watch_pool           ← BuildStrongStockTrackingUseCase

        ↓ (快速生成/全量重建最后一步)

复盘生成（复盘模块-阶段一 最后一步）
  post_market_recap_snapshot        ← BuildDailyReviewReadModelJob

        ↓

展示（复盘模块-阶段二）
  RecapPage ← GET /api/v2/daily-review
```
