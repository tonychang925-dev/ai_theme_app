## 0. 总体结论

盘后复盘模块下一步不应该继续堆报告文案，而应该升级为：

```
盘后事实汇总
  ↓
交易体系判断
  ↓
次日作战计划
  ↓
结构化 DailyReview V2
  ↓
前端 / Notion / 盘前必读共用
```

也就是从现在的**复盘报告生成器**升级为**交易体系驱动的盘后决策引擎**。

PDF 的核心思想抽象成四个权重：

| 层级 | 权重 | 内容 |
|------|------|------|
| 主线判断 | 35% | 逻辑成立 + 市场承认 |
| 市场情绪 / 周期 | 30% | 情绪周期决定能不能出手 |
| 龙头核心 | 20% | 决定做谁 |
| 买点计划 | 15% | 决定明天怎么做 |

这四层必须成为盘后复盘的主结构，而不是只在报告文字里体现。

## 一、当前模块现状判断

### 1.1 已经具备的好基础

当前 `BuildPostMarketRecapJob` 已经不是简单生成文本，它已经串起了 Layer A/B/C/D：

- Layer A/B：evidence / cycle / identity / mainline_state
- Layer C：strong_watch_pool
- Layer D：弱转强候选读取
- readiness guard
- recap_doc
- post_market_recap_snapshot
- DailyReview / DailyReview V2

代码里已经明确先跑 Layer A/B 前置任务，再跑 Layer C 强势股观察池，D1 只读取已有候选，不在复盘里重新做选股。这个方向是正确的。

`PostMarketReadinessService` 已经检查核心表：

- `subject_stock_daily_snapshot`
- `theme_cycle_judgement_v2`
- `money_flow_enhanced`
- `strong_stock_watch_history`
- `dragon_tiger_object`

关键表缺失时会返回 `failed_precondition`。`BuildPostMarketRecapJob` 里也已经有 readiness guard，未 ready 时不写正常快照。

`PostMarketDailyReviewV2Builder` 已经定义了完整模块容器：

- `market_summary`
- `theme_reviews`
- `theme_capital_reviews`
- `strong_stock_reviews`
- `watchlist_reviews`
- `stock_capital_reviews`
- `abnormal_reviews`
- `money_flow_reviews`
- `dragon_tiger_reviews`
- `diagnostics`

这些是非常重要的基础。

### 1.2 当前最大问题

当前盘后复盘还停留在"结构化展示层"，没有完全变成"交易决策层"。

例如 V1 `theme_reviews` 中（`build_post_market_recap_job.py:1047-1054`）：

```python
"capital_validation": "NEUTRAL",
"event_chain": [],
"action_advice": "",
"conclusion": "",
```

**系统能告诉你**：题材强度、周期状态、资金流入、有哪些股票。

**但还不能稳定回答**：明天能不能做？是主做、观察、放弃还是空仓？做哪个题材？做哪个核心股？什么条件下做？什么条件下放弃？

## 二、目标架构设计

### 2.1 新增核心模块：PostMarketDecisionEngine

建议新增一个独立的决策引擎，不要继续把所有逻辑塞进 `BuildPostMarketRecapJob`。

建议目录结构：

```
stock_processing_service/
  domain/
    services/
      post_market_decision/
        __init__.py
        market_environment_engine.py
        theme_decision_engine.py
        leader_core_engine.py
        next_day_watchlist_engine.py
        trading_principle_engine.py
        post_market_decision_engine.py
```

整体结构：

```
PostMarketDecisionEngine
  ├── MarketEnvironmentEngine        # 大环境与情绪周期
  ├── ThemeDecisionEngine            # 主线/支线/放弃题材判断
  ├── LeaderCoreEngine               # 龙头/龙二/卡位/补涨/淘汰判断
  ├── NextDayWatchlistEngine         # 次日观察计划
  └── TradingPrincipleEngine         # 总交易原则与仓位约束
```

`BuildPostMarketRecapJob` 只负责 orchestration：

```
读取事实
  ↓
调用 PostMarketDecisionEngine
  ↓
写入 recap_doc.decision_reviews
  ↓
生成 DailyReview V2
  ↓
生成 report sections
```

`NewChainPostMarketReportBuilder` 以后只做文案渲染，不再承担核心业务判断。sections 应变成结构化决策对象的展示结果，而不是判断真源。

## 四、评分与决策规则设计

### 4.1 总分公式

用 PDF 的四权重作为最终决策分：

```
decision_score =
  mainline_score * 0.35
+ market_environment_score * 0.30
+ leader_core_score * 0.20
+ setup_plan_score * 0.15
```

### 4.2 主线分 mainline_score

来源：`theme_cycle_judgement_v2.mainline_strength_score`、`theme_mainline_identity_registry` / `mainline_state_daily`、event_chain impact、capital_validation、subject_rank / JYHF 题材热度。

```
mainline_score =
  logic_score * 0.4
+ market_recognition_score * 0.4
+ continuity_score * 0.2
```

| 子分 | 含义 | 来源 |
|------|------|------|
| `logic_score` | 政策/技术/产业趋势/重大事件/新颖度 | event_theme_map, news_event, subject_history |
| `market_recognition_score` | 涨停数量、资金流入、龙头强度、题材内扩散程度 | capital_flow, strong_stock_watch |
| `continuity_score` | 连续活跃天数、是否有新催化、是否从启动进入发酵 | theme_cycle, subject_rank_daily |

### 4.3 市场环境分 market_environment_score

| mode | 分数范围 | 仓位上限 | 含义 |
|------|---------|---------|------|
| attack | 80-100 | 1.0 | 主线明确、情绪好、量能放大 |
| normal | 60-79 | 0.5 | 有主线但分歧存在 |
| defense | 40-59 | 0.3 | 涨跌分化、情绪分歧，只允许核心机会 |
| wait | 0-39 | 0.0 | 跌停扩大、主线退潮、禁止开新仓 |

**attack 条件**：market_health_score >= 75 AND limit_up >= 60 AND limit_down <= 5

**normal 条件**：market_health_score >= 55 AND limit_up >= 35

**defense 条件**：market_health_score >= 35

**wait 条件**：其余

### 4.4 龙头核心分 leader_core_score

```
leader_core_score =
  purity_score * 0.25
+ leading_score * 0.25
+ capital_score * 0.20
+ structure_score * 0.20
+ resilience_score * 0.10
```

| 子分 | 含义 |
|------|------|
| `purity_score` | 题材正宗性 |
| `leading_score` | 领涨性 / 带动性 |
| `capital_score` | 资金确认 |
| `structure_score` | K线结构 / 位置 |
| `resilience_score` | 分歧日抗跌承接 |

### 4.5 买点计划分 setup_plan_score

```
setup_plan_score =
  support_score * 0.35
+ auction_observable_score * 0.25
+ invalid_condition_clarity * 0.20
+ risk_reward_score * 0.20
```

> 盘后只生成"计划"，不直接确认买点；盘前 9:25 后再由竞价确认模块二次确认。

### Phase 2：实现 MarketEnvironmentEngine（2 天）

**新增文件**：`stock_processing_service/domain/services/post_market_decision/market_environment_engine.py`

**输入**：report_context.market、market_summary、index_quotes、涨跌停家数、market_health_score、breadth_status、sentiment_status

**输出**：`MarketEnvironmentReview`

**核心规则**：

```python
def classify_market_mode(market: dict) -> str:
    score = float(market.get("market_health_score") or 0)
    limit_down = int(market.get("limit_down_count") or 0)
    limit_up = int(market.get("limit_up_count") or 0)

    if score >= 75 and limit_up >= 60 and limit_down <= 5:
        return "attack"
    if score >= 55 and limit_up >= 35:
        return "normal"
    if score >= 35:
        return "defense"
    return "wait"
```

**验收**：市场数据缺失时 market_mode = "wait"、position_limit <= 0.3；偏弱时禁止非主线追涨；强市时允许主线核心机会。

### Phase 3：实现 ThemeDecisionEngine（3-4 天）

**新增文件**：`stock_processing_service/domain/services/post_market_decision/theme_decision_engine.py`

**输入**：theme_context_map、cycles、capital_flow、stock_facts、event_chain、MarketEnvironmentReview

**核心规则**：

```python
def decide_theme(row, market_env):
    if not row.final_mainline_alive:
        return "fade_avoid"
    if row.fade_risk_score >= 70:
        return "risk_watch"
    if row.mainline_strength_score >= 70 and row.capital_validation == "positive":
        if market_env.market_mode in {"attack", "normal"}:
            return "mainline_focus"
        return "watch_weak_to_strong"
    if row.mainline_strength_score >= 50:
        return "strong_branch_watch"
    return "reject"
```

**action_advice 生成规则**：

| decision | action_advice |
|----------|---------------|
| `mainline_focus` | 主线重点，优先看核心前排承接 |
| `watch_weak_to_strong` | 主线仍活但处于分歧，只关注核心前排弱转强 |
| `strong_branch_watch` | 强分支观察，等待资金继续确认 |
| `risk_watch` | 退潮风险上升，只观察不追涨 |
| `fade_avoid` | 退潮或主线失效，回避 |
| `reject` | 非主线或证据不足，放弃 |

**验收**：

1. `capital_validation` 不再全是 NEUTRAL
2. `action_advice` 不能为空
3. `conclusion` 不能为空
4. 非主线题材必须能输出 reject / avoid
5. 退潮题材必须输出 fade_avoid 或 risk_watch

---

### Phase 4：实现 LeaderCoreEngine（3-5 天）

**新增文件**：`stock_processing_service/domain/services/post_market_decision/leader_core_engine.py`

**输入**：strong_stock_watch_history、money_flow_enhanced、stock_position_judgement、stock_pattern_judgement、subject_stock_daily_snapshot、theme_leader_candidate

**龙头角色规则**：

| 角色 | 条件 |
|------|------|
| `leader` | watch_score >= 80、leader_composite_score 前1、capital 正向、带动性强 |
| `sub_leader` | watch_score >= 70、排名前3、资金确认、独立强度 |
| `switch_leader` | 原龙头分歧时逆势走强、资金加强、形态更强 |
| `supplement` | 题材内低位补涨，非第一波核心 |
| `reject` | 非核心、无资金、无支撑、形态破坏 |

**验收**：每个非 reject 股票必须有 role、core_score、money_flow、kline、support、rationale、invalid_condition

### Phase 5：实现 NextDayWatchlistEngine（2-3 天）

**新增文件**：`stock_processing_service/domain/services/post_market_decision/next_day_watchlist_engine.py`

**分类规则**：

| 分类 | 条件 |
|------|------|
| 重点观察 | market_mode in attack/normal、theme_decision = mainline_focus、role in leader/sub_leader/switch_leader |
| 弱转强观察 | theme_decision = watch_weak_to_strong、support_score >= 70、strong_gene_score |
| 风险观察 | fade_risk_score 高、高位放量滞涨、资金背离 |
| 放弃观察 | 非主线、非核心、无支撑、无资金确认 |

**验收**：每条 watchlist 必须有 category、reason、action、buy_condition、invalid_condition、suggested_position。没有买入条件和失效条件的，不允许进入"重点观察"。

### Phase 6：实现 TradingPrincipleEngine（2 天）

**新增文件**：`stock_processing_service/domain/services/post_market_decision/trading_principle_engine.py`

**输入**：MarketEnvironmentReview、ThemeDecisionReview[]、LeaderCoreReview[]、WatchlistReviewV2[]

**输出**：`recap_doc.trading_principle`、`DailyReviewV2.trading_principle`

**规则**：

```python
if market_env.market_mode == "wait":
    allow_trade = False; position_limit = 0; main_strategy = "空仓等待"
elif no_mainline_theme:
    allow_trade = False; position_limit = 0; main_strategy = "无主线，不开新仓"
elif market_env.market_mode == "defense":
    allow_trade = True; position_limit = 0.3; main_strategy = "只做主线核心弱转强"
elif market_env.market_mode == "normal":
    allow_trade = True; position_limit = 0.5; main_strategy = "主线核心优先"
else:
    allow_trade = True; position_limit = 1.0; main_strategy = "主线龙头优先"
```

### Phase 7：集成到 BuildPostMarketRecapJob（2 天）

**优化后流程**：

```
1. Layer A/B prerequisites
```

```python
decision_result = self._decision_engine.execute(
```

### Phase 8：DailyReview V2 优化

1. **V2 Builder 职责收窄**：只做字段映射、字段校验、module coverage、兼容 fallback；不做主线判断、动作建议、龙头识别、买点推演。这些全部交给 `PostMarketDecisionEngine`。

2. **优先读取新字段**：
   - 题材读取顺序：`theme_decision_reviews > theme_reviews > report_context.cycles > legacy sections`
   - 强势股读取顺序：`strong_stock_decision_reviews > strong_stock_reviews > strong_watch_history > promoted_pool_preview > top_candidates`
   - 观察清单读取顺序：`watchlist_reviews > generated from decision objects > legacy sections`

3. **fallback 显式降级**：凡是使用 fallback 的字段写入 `diagnostics.fallback_used` 和 `confidence` 分数。

## 十、MVP 最小可行版本

第一版不追求完美。MVP 只要做到：

1. `trading_principle` 能输出能不能做、仓位上限、禁止动作
2. `theme_reviews` 能输出 `action_advice` 和 `conclusion`
3. `capital_validation` 不再固定 NEUTRAL
4. `watchlist_reviews` 能输出次日观察条件和失效条件
5. 前端主表优先读 DailyReview V2

这五点完成后，盘后复盘就会从"总结过去"跨到"指导明天"。

---

## 十一、最终目标形态

盘后复盘页面直接回答 6 个问题：

1. 今天市场处于什么环境？
2. 明天能不能交易？
3. 如果能交易，仓位上限是多少？
4. 哪些题材是主线，哪些只是支线，哪些必须放弃？
5. 主线里谁是龙头、龙二、卡位、补涨，谁要淘汰？
6. 明天具体盯什么，满足什么条件才出手，什么情况必须放弃？

这才是 PDF 要求的正确交易体系。
