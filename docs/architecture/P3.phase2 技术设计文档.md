# P3.phase2 技术设计文档

## 盘前必读 + 每日复盘对象模型与生成流程

---

## 1. 设计目标

P3.phase2 的目标不是简单生成一篇“行情描述文章”，而是构建一套可重复、可落库、可回测、可供 LLM 结构化输出的对象体系，把交易复盘和盘前计划统一到同一套数据模型中。

### 核心目标

1. 把“市场—题材—龙头—操作计划”拆开建模，避免混写。
2. 盘前与盘后共用同一底层对象，仅在视图层差异化输出。
3. 支持：
    - 每日盘前必读生成
    - 每日复盘生成
    - 题材强度排序
    - 龙头识别与阶段判断
    - 明日交易计划生成
4. 支持后续接入：
    - LLM 结构化抽取
    - 规则评分
    - 历史回测
    - 题材演化轨迹跟踪

---

## 2. 总体架构

建议把 P3.phase2 收敛为 **“四层对象 + 两套视图”**：

### 2.0 当前实施冻结口径

虽然历史设计曾从“题材复盘卡片”展开，但结合当前真实交易资料与现有基础，`P3.phase2` 的**实施真源**应先冻结为 3 张表：

1. `theme_mainline_judgement`
2. `theme_cycle_judgement_v2`
3. `theme_leader_candidate`

然后：

- `每日复盘` = 这 3 张表的结果展示
- `盘前推荐` = 基于昨晚这 3 张表的承接验证

因此：

- `theme_recap_snapshot`
- `daily_recap_summary`

仍然保留为汇总视图层对象，但不应先于上述 3 张真源表实现。

### 四层对象

1. `theme_recap_snapshot`
题材主卡片对象
2. `theme_driver_event`
题材驱动与证据对象
3. `theme_leader_judgement` / `theme_stage_judgement`
龙头判断与题材阶段判断对象
4. `daily_recap_summary`
全局市场汇总对象

### 两套视图

1. **盘前必读视图**
偏候选、预判、预案
2. **每日复盘视图**
偏结果、归因、验证、明日计划

### 2.1 需要补充的事实层约束

当前这套对象分层方向正确，但如果直接进入实现，`theme_recap_snapshot` 会承载过多职责，后续容易变成“题材总表”，导致：

- 事实字段与解释字段混写
- 规则输出与 LLM 输出互相覆盖
- 盘前/盘后视图复用时难以对账

因此建议在 P3.phase2 正式实现前，先冻结一个额外的**事实层对象**：

## `theme_strength_metrics`

它负责承接题材强度与梯队结构的真源数据，不由 LLM 直接生成。

建议字段：

```
{
  "trade_date":"2026-07-08",
  "theme_name":"商业航天",
  "theme_code":"SUBJ_001",
  "limit_up_count":6,
  "frontline_count":3,
  "diffusion_count":9,
  "leader_stock_id":"600343",
  "leader_stock_name":"航天动力",
  "leader_pct_chg":10.01,
  "top_stock_names":["航天动力","上海沪工","天银机电"],
  "board_effect_score":86,
  "continuity_score":74
}
```

这层应主要来自：

- `subject_stock_daily_snapshot`
- `theme_stock_leaderboard`
- `stock_abnormal_event`
- `JYHF` 题材股票池与题材事件

不建议由 LLM 直接推断：

- `limit_up_count`
- `leader_stock`
- `frontline_count`
- `board_effect_score`

这些都应该先由规则层给出。

### 2.2 建议的收敛关系

建议把对象关系明确为：

- `theme_strength_metrics`：题材强度事实层
- `theme_driver_event`：题材驱动事实层
- `theme_leader_judgement`：龙头判断层
- `theme_stage_judgement`：阶段判断层
- `theme_recap_snapshot`：汇总卡片层
- `daily_recap_summary`：市场级总览层

也就是说：

- `theme_recap_snapshot` 不再作为“题材真源总表”
- 它应视为一个**聚合结果对象**
- 真正的事实来源应分散在上面四类对象中

### 2.3 三张真源表的职责冻结

#### `theme_mainline_judgement`

回答：

- 今天市场主线是谁？
- 它为什么能算主线？

最低字段要求：

- `event_chain_score`
- `event_chain_continuity_score`
- `market_recognition_score`
- `mainline_stability_score`
- `is_main_theme`
- `theme_tier`
- `limit_up_count`
- `conclusion`
- `source_version`
- `rule_version`

#### `theme_cycle_judgement_v2`

回答：

- 主线当前处于哪个周期位置？

最低字段要求：

- `is_start`
- `is_fermentation`
- `is_divergence`
- `is_rebound`
- `is_climax`
- `is_fade`
- `primary_cycle_stage`
- `leader_status`
- `board_effect_status`
- `action_bias`
- `confidence`
- `conclusion`
- `source_version`
- `rule_version`

#### `theme_leader_candidate`

回答：

- 主线内部谁是龙头、龙二、卡位、补涨、套利？

最低字段要求：

- `purity_score`
- `leading_score`
- `capital_score`
- `structure_score`
- `resilience_score`
- `composite_score`
- `candidate_rank`
- `role_label`
- 轻量事实冗余：
  - `is_limit_up`
  - `limit_up_type`
  - `turnover_rate`
  - `volume_ratio`
  - `main_net_inflow`
  - `is_new_stock`
- `source_version`
- `rule_version`

### 2.4 字段来源与生成责任

#### A. 原始事实输入

来自：

- `jyhf_history`
- `news_event / event_theme_map`
- `subject_stock_daily_snapshot`
- `theme_stock_rollup`
- `stock_abnormal_event`

#### B. 规则层生成

生成：

- `event_chain_score`
- `event_chain_continuity_score`
- `market_recognition_score`
- `mainline_stability_score`
- `primary_cycle_stage`
- `action_bias`
- `candidate_rank`
- `role_label`

#### C. 展示层汇总

生成：

- 每日复盘页面
- 盘前推荐页面
- Notion 页面输出

#### D. LLM 允许生成

仅允许：

- 总结语句
- 风险提示
- 展示性解释文字

#### E. LLM 不允许覆盖

明确禁止覆盖：

- 主线判断
- 周期状态
- 龙头角色标签
- 候选排序
- 各类事实分数

## 3. 对象模型设计

---

### 3.1 题材复盘对象

## `theme_recap_snapshot`

这是最核心的“题材卡片对象”，每个题材每天生成 1 条。

但建议把它严格定义为：

- **汇总卡片对象**
- 不是事实主表
- 不直接承担全部真源字段

### 字段定义

```
{
  "trade_date":"2026-07-08",
  "theme_name":"商业航天",
  "theme_code":"SUBJ_001",
  "strength_score":88,
  "is_main_theme":true,
  "stage":"确认期",
  "leader_stock":"航天动力",
  "leader_confidence":0.87,
  "trade_style_hint":"1进2",
  "summary":"政策催化叠加发射预期，板块联动增强，核心股辨识度提升。",
  "tomorrow_plan":"优先看龙头分歧后的回封，其次看同梯队1进2补位机会。",
  "risk_notes": [
"若竞价不强，谨防冲高回落",
"若板块仅剩单点强势，需降级处理"
  ]
}
```

### 字段解释

- `trade_date`：交易日
- `theme_name`：题材名
- `theme_code`：题材编码或 `subject_key`
- `strength_score`：题材综合强度分
- `is_main_theme`：是否主线
- `stage`：题材阶段
- `leader_stock`：当前龙头/核心高标
- `leader_confidence`：龙头置信度
- `trade_style_hint`：适合的交易风格
- `summary`：一句话总结该题材今日状态
- `tomorrow_plan`：明日交易计划摘要
- `risk_notes`：风险提示数组

### 作用

- 盘前：输出“今日候选题材卡”
- 盘后：输出“今日题材复盘卡”

### 优化建议

实现时建议将以下字段视为“聚合结果字段”，而不是独立真源：

- `strength_score`
- `stage`
- `leader_stock`
- `leader_confidence`
- `summary`
- `tomorrow_plan`
- `risk_notes`

其中：

- `strength_score` 应由 `theme_strength_metrics` 计算得出
- `stage` 应主要来自 `theme_stage_judgement`
- `leader_stock` 应主要来自 `theme_leader_judgement`
- `summary / tomorrow_plan / risk_notes` 才适合交给 LLM 做结构化归纳

### 3.2 题材驱动与证据对象

## `theme_driver_event`

这个对象用来回答：**为什么今天炒它？**

《国产算力》《商业航天》的组织方式非常适合抽象成这一层：先列逻辑背景与消息，再列事件，再映射到投资机会。

### 字段定义

```
{
  "trade_date":"2026-07-08",
  "theme_name":"国产算力",
  "event_time":"2026-07-08 08:15:00",
  "event_type":"产业订单",
  "driver_level":"行业级",
  "summary":"大厂资本开支上修，国产算力链订单兑现预期增强。",
  "source":"财联社",
  "is_confirmed":true,
  "importance_score":92
}
```

### 字段解释

- `event_type` 建议枚举：
    - 政策
    - 产业
    - 技术突破
    - 订单
    - 财报
    - 发射/试验
    - 社交扩散
    - 传闻
- `driver_level` 建议枚举：
    - 国家级
    - 行业级
    - 公司级
    - 传闻级
- `is_confirmed`：是否为正式确认信息
- `importance_score`：驱动事件重要性

### 作用

- 盘前：识别“今日可炒逻辑”
- 盘后：确认“今日真实驱动主因”

### 3.3 龙头判断对象

## `theme_leader_judgement`

这个对象用来回答：**谁是龙头，谁只是跟风，谁是龙二、中军、套利？**

《如何抓涨停股》明确给出龙头判断框架：看首板换手、二板放量分歧转一致、唯一性、市场热度、封单质量、快速回封能力、辨识度与情绪位置。

### 字段定义

```
{
  "trade_date":"2026-07-08",
  "theme_name":"商业航天",
  "stock_id":"600343",
  "stock_name":"航天动力",
  "leader_type":"龙头",
  "confidence":0.9,
  "evidence": [
    {"type":"advance_order", "value":"最先完成二板确认"},
    {"type":"seal_quality", "value":"封单稳定，分歧后快速回封"},
    {"type":"theme_purity", "value":"题材映射正宗"},
    {"type":"market_attention", "value":"板块内辨识度最高"}
  ]
}
```

### `leader_type` 建议枚举

- 龙头
- 龙二
- 中军
- 核心高标
- 套利
- 观察

### 作用

- 盘前：输出龙头候选与核心标
- 盘后：确认真龙、龙二、中军与失败跟风

### 3.4 题材阶段判断对象

## `theme_stage_judgement`

这个对象用来回答：**这个题材现在处在什么阶段？**

### 字段定义

```
{
  "trade_date":"2026-07-08",
  "theme_name":"国产算力",
  "stage":"高位分歧期",
  "confidence":0.82,
  "evidence": [
    {"type":"board_effect", "value":"板块内仍有梯队，但掉队增多"},
    {"type":"leader_status", "value":"核心高标高位震荡"},
    {"type":"follow_status", "value":"跟风股承接转弱"},
    {"type":"flow_signal", "value":"板块资金集中度下降"}
  ],
  "risk_notes": [
"高位接力风险增加",
"若次日竞价走弱，谨防退潮扩散"
  ]
}
```

### `stage` 建议统一枚举

- 观察期
- 发酵期
- 确认期
- 加速期
- 高位分歧期
- 退潮期

### 作用

- 盘前：阶段预判
- 盘后：阶段验证

### 3.5 全局汇总对象

## `daily_recap_summary`

这是整个系统的总入口。

### 字段定义

```
{
  "trade_date":"2026-07-08",
  "market_summary":"市场情绪修复，主线聚焦商业航天，国产算力高位分歧，短线更适合做1进2而非盲目追高。",
  "main_themes": ["商业航天","卫星互联网"],
  "failed_themes": ["部分高位AI分支"],
  "tomorrow_watchlist": ["航天动力","某卫星互联网核心股"],
  "tomorrow_plan":"优先看主线龙头分歧后的承接与1进2补涨，回避非主线杂毛。"
}
```

### 作用

- 盘前：生成“今日作战纲要”
- 盘后：生成“当日市场总结 + 明日计划”

### 边界建议

`daily_recap_summary` 应只承接**市场级结论**，不要重复承载过多题材细节。

建议它只负责：

- 市场一句话总结
- 主线题材列表
- 失败题材列表
- 明日观察名单
- 明日总计划

不建议它直接再存储：

- 题材详细驱动
- 个股级龙头证据
- 题材内梯队细节

这些应分别留在：

- `theme_driver_event`
- `theme_leader_judgement`
- `theme_strength_metrics`

## 4. 判定规则表

---

### 4.1 主线题材判定规则

根据你上传的流程图，以及《如何抓涨停股》中对题材、板块效应、市场热度的要求，主线题材判断至少要看以下维度：

### 核心维度

1. **消息驱动是否明确**
    - 是否有新政策、新事件、新产业催化
2. **板块扩散是否成立**
    - 是否有多只个股联动
    - 是否出现首板梯队
3. **市场认知是否形成**
    - 新闻、社交、盘口辨识度是否上升
4. **持续性是否具备**
    - 不是一日游脉冲
5. **资金是否认可**
    - 核心股换手、封单、回封表现是否健康

### 主线建议输出条件

当以下 3 项以上成立，可判定为主线候选：

- 有明确驱动事件
- 有 2~3 只以上联动个股
- 出现核心领涨股
- 板块效应明显
- 市场情绪匹配

---

### 4.2 龙头判定规则

《如何抓涨停股》对“二板定龙头”的逻辑很完整，可以直接转为规则。

### 龙头评分维度

1. **首板质量**
    - 首板优先换手板
    - 一字板不优先
    - 换手率 > 15% 加分
2. **二板确认**
    - 二板放量分歧转一致，加分
    - 二板缩量直接封死，也可加分
    - 二板炸板回封质量高，加分
3. **题材唯一性**
    - 是否最正宗
    - 是否最先走出二板
    - 是否题材唯一映射
4. **市场热度**
    - 是否有板块扩散
    - 是否讨论度高
5. **盘口气质**
    - 封单稳定
    - 分歧中快速回封
    - 辨识度最高
6. **情绪位置**
    - 情绪冰点修复第一波更优
    - 高位退潮后硬顶减分

### 输出建议

- 总分最高且无明显硬伤 → 龙头
- 次高但辨识度稍弱 → 龙二
- 体量大、趋势稳、带板块但不一定最强连板 → 中军
- 纯跟风、无独立辨识度 → 套利/观察

---

### 4.3 题材阶段判定规则

### 观察期

- 有零散消息
- 尚无明显板块效应

### 发酵期

- 开始出现多股异动
- 有首板或局部涨停

### 确认期

- 有龙头雏形
- 板块梯队开始形成
- 市场开始集中讨论

### 加速期

- 龙头连续晋级
- 跟风补涨明显
- 板块联动增强

### 高位分歧期

- 龙头强，跟风掉队
- 炸板增多
- 日内大幅波动

### 退潮期

- 板块效应明显减弱
- 仅剩个别高标活跃
- 资金开始切新题材

---

### 4.4 强势股与买点辅助规则

《如何找出牛股》给出的量价形态可作为个股强弱辅助规则：高量不破、倍量不穿、缺口不补、均线多头、放量涨缩量跌、分时拉升有量回落无量、具备深广度题材、创新高与连贯性。

### 可转为辅助信号

- `volume_pattern_score`
- `ma_trend_score`
- `breakout_quality_score`
- `continuity_score`

这些不直接决定龙头，但可作为：

- 强势股筛选
- 核心股补位判断
- 弱转强前置过滤

### 工程建议

这一组规则建议优先只作为辅助评分字段沉淀，不直接进入第一批“龙头定性结论”。

建议先产出：

- `volume_pattern_score`
- `ma_trend_score`
- `breakout_quality_score`
- `continuity_score`

后续再由判断层消费这些字段。

---

### 4.5 盘前集合竞价规则

《集合竞价》给出的几个形态非常适合盘前信号提取。

### 基本规则

1. 9:20~9:25 走势要稳定
2. 临近结束不能急跌
3. 优先红盘区强势结构
4. 9:24~9:25 若抢筹明显，加分

### 典型强势竞价形态

- 倒L型 + 上坡型
- 红盘区阶梯型
- 红盘区锥形 + U形
- 红盘区上翘一字型。

### 竞价信号适用场景

- 弱转强
- 1进2 竞价确认
- 龙头次日是否有承接

### 优先级建议

集合竞价规则有价值，但不建议作为 `P3.phase2` 首批主路径能力。

原因：

- 当前 `P3.phase1` 已经稳定落地的是日频对象与题材事件流
- 集合竞价判断需要更稳定的分钟级或盘前快照真源
- 若提前纳入 `P3.phase2` 主路径，容易把阶段目标拉偏到高频实时

因此建议：

- 在 `P3.phase2` 中保留字段与接口预留
- 将真正的竞价形态规则计算后移到 `P3.phase3`

---

## 4.6 字段所有权与生成边界

为了避免后续实现中“规则层”和“LLM 层”反复争夺字段定义，建议在本阶段冻结以下口径。

### 规则层必须产出

- `limit_up_count`
- `frontline_count`
- `diffusion_count`
- `leader_stock`
- `leader_stock_id`
- `leader_pct_chg`
- `main_themes`
- `failed_themes`
- `tomorrow_watchlist`（候选集合）

### LLM 可补充生成

- `summary`
- `tomorrow_plan`
- `risk_notes`
- `stage` 的解释文本
- `leader` 的证据组织文本

### LLM 不应直接覆盖

- 股票事实字段
- 涨停家数
- 龙头股票主键
- 题材主线列表
- 题材强度基础计数

这条边界建议在工程实现时写入：

- schema
- prompt contract
- phase contract

## 9. 工程落地建议

### 9.1 存储建议

建议优先按 6 张表落地：

1. `theme_strength_metrics`
2. `theme_driver_event`
3. `theme_leader_judgement`
4. `theme_stage_judgement`
5. `theme_recap_snapshot`
6. `daily_recap_summary`

其中建议实施顺序也按这个顺序推进，而不是反过来先做 `summary`。

### 9.2 生成方式建议

采用 **规则预处理 + LLM 结构化总结**：

- 规则层负责：
    - 数据聚合
    - 初步评分
    - 候选过滤
- LLM 层负责：
    - 归因总结
    - 阶段判断解释
    - 明日计划生成
    - 风险提示归纳

### 进一步建议

可把工程实现收敛为两段：

1. `fact builder`
   - 生成 `theme_strength_metrics`
   - 生成 `theme_driver_event`
   - 生成候选 `leader/stage` 输入上下文

2. `judgement + summary builder`
   - 输出 `theme_leader_judgement`
   - 输出 `theme_stage_judgement`
   - 输出 `theme_recap_snapshot`
   - 输出 `daily_recap_summary`

这样更符合当前项目已经落地的 `P3.phase1` 架构现实。

### 9.3 后续可扩展字段

后续可以继续加：

- `board_effect_score`
- `auction_signal_score`
- `seal_quality_score`
- `theme_purity_score`
- `continuity_score`

这些字段适合做量化辅助，而不必全交给 LLM 解释。

---

## 10. 最终结论

P3.phase2 最合理的收敛方式是：

- 用 `theme_driver_event` 解决“为什么炒”
- 用 `theme_leader_judgement` 解决“谁在带队”
- 用 `theme_stage_judgement` 解决“题材走到哪一步”
- 用 `theme_recap_snapshot` 解决“每个题材怎么总结、明天怎么做”
- 用 `daily_recap_summary` 解决“全局市场结论与交易纲要”

这样一来，**盘前必读和每日复盘不再是两套松散文稿，而是同一底层对象体系下的两种输出视图**。
