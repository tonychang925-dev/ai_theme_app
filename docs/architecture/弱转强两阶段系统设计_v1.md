# 弱转强两阶段系统设计 v1

## 1. 文档定位

本文档用于定义“弱转强”选股系统的 v1 架构与落地边界，作为后续持续迭代的基线文档。

- 当前状态：`v1.2`
- 目标：从“单点筛选脚本”升级为“盘后候选池 + 盘前竞价确认”的系统化能力
- 迭代原则：后续所有优化均在本文件持续演进，不另起重复方案文档

---

## 2. 目标与范围

### 2.1 目标

构建两阶段弱转强系统：

1. 盘后选股层：基于每日复盘已准备事实生成下一交易日候选池（高召回）
2. 盘前竞价层：对候选池做确认（高精度）

### 2.2 非目标（v1 不做）

1. 盘前全市场海选
2. 复杂模型驱动的竞价图形识别
3. 全量盘中实时回流引擎

---

## 3. 核心架构

### 3.1 两阶段职责

1. 盘后选股层回答：`明天哪些票值得盯竞价`
2. 盘前层回答：`这些候选里谁真正出现弱转强确认`

边界说明：

- 每日复盘负责准备主线、周期、强势股、资金、异动、K线等事实并生成复盘快照。
- 弱转强盘后选股显式生成 D1 候选池；D1 未执行不得影响每日复盘主体展示。

### 3.2 关键原则

1. 盘前模块只确认候选池，不直接扫全市场
2. 先规则型 MVP，再做模型增强
3. 每条信号必须可解释（入选原因 + 扣分原因 + 证据）
4. 盘前确认层不得将非候选股票输出为 A/B 正式信号
5. 候选层采用三分流：`formal / observe_only / reject`
6. `fade_confirmed` 才是硬否决；`fade_watch` 仅降权，不直接封杀
7. 盘前模块输出必须绑定候选池记录（`candidate_id`）
8. 双日期协议必须显式：`candidate_trade_date` 与 `confirm_trade_date`（`confirm_trade_date = next_trade_date`）
9. 阶段2只消费 `pool_entry_type = formal`，`observe_only` 仅用于跟踪与回放

## 5. 阶段 A：盘后候选池（高召回）

### 5.1 入池规则

#### 必要条件（硬门槛）

1. 当日必须先弱：`pct_chg <= -1` 且 `limit_up=false`。上涨、平盘、涨停与微跌噪声样本都不属于 D1 盘后弱转强候选。
2. 前期强势背景成立（龙头/次龙/前排或强势结构达标），且近端强势基因仍在有效窗口内。
3. 当前处于分歧修复窗口（排除退潮确认末端）
4. 支撑位地板成立（`support_strength >= 25`）
5. 周期硬拒仅 `fade_confirmed=true`

输入边界：

- D1 只消费强势股观察池输出，不做全市场直扫。
- C 层负责 7 个交易日动态滚动、过期剔除和再次强势后的续命。
- D1 在构建候选时仍复核近端强势时效，避免 C 池残留状态或窗口失效对象直接进入弱转强候选。

#### 评分条件（非否决）

1. 弱势类型与强度：`big_negative_line` / `upper_shadow` / `bad_limit_up` / `fake_break` / `high_open_low_close`
   - 类型分类只能在“当日先弱”硬门槛通过后执行。
   - `bad_limit_up` 指前一交易日涨停后的当日转弱，不表示当日涨停可以进入 D1。
2. 连续弱势项降级为评分，不再一票否决：`day_weak_score + prev_day_weak_score`
3. 支撑体系：缺口、前板/前高/前低、MA5/MA10
4. 主线与地位：主线归属、板块排序、联动潜力
5. 量价状态：缩量分歧、承接保留、关键位不失守
6. `fade_watch` 动态扣分（随 `mainline_strength_score` 分层），不做硬拒

### 5.2 出池规模控制

1. 每日候选池规模建议：`30-120`
2. 候选对象必须包含“次日竞价确认目标条件”

### 5.3 候选三分流（v1.2）

1. `formal`：进入阶段2正式竞价确认
2. `observe_only`：仅跟踪/回放，不进入A/B正式确认流
3. `reject`：直接淘汰
4. 建议阈值基线：
   - `formal`: `final_mainline_alive=true && !fade_confirmed && mainline_strength_score>=60 && support_strength>=45`
   - `observe_only`: `!fade_confirmed && mainline_strength_score>=40 && leader_alive_score>=45 && event_continuity_score>=30 && support_strength>=70`

## 6. 阶段 B：盘前竞价确认（高精度）

### 6.1 输入

1. 当日候选池
2. 9:20-9:25 竞价数据
3. 同题材/板块竞价联动数据
4. 周期联动字段：`cycle_state/mainline_strength_score/fade_watch/fade_confirmed/pool_entry_type`

### 6.2 四维评分（总分 100）

1. 价格强度：30
2. 形态稳定：25
3. 最后一分钟抢筹：25
4. 板块联动：20

### 6.3 风险扣分（0-30）

1. 尾段急跌
2. 红盘失守
3. 冲高回落风险
4. 板块同步转弱

### 6.4 MVP 硬规则（v1.2）

1. 必须来自候选池
2. 必须 `pool_entry_type = formal`
3. `fade_confirmed = true` 直接禁入
4. 9:20-9:25 不可大起大落
5. 9:24-9:25 需抢筹增强或承接增强
6. 竞价结束需红盘或站稳关键承接位
7. 不可尾段急跌
8. 板块不可明显退潮（`fade_watch` 场景降级为扣分，不硬拒）

### 6.5 硬规则与评分项分离

1. 硬规则只负责“是否保留在正式信号流”
2. 评分项只负责“合格样本内部强弱排序”
3. 硬规则失败时，输出 `C` 或 `X`，不得通过“高分补偿”绕过
4. 评分项不承担一票否决职责

---

## 7. 信号分级

### 7.1 分级标准

1. A 级（强确认）：`confirmation_score >= 75` 且关键项完整满足
2. B 级（观察）：`55 <= score < 75` 或存在单项短板
3. C 级（放弃）：`score < 55` 或触发高风险硬条件
4. X 级（数据异常/暂不判定）：竞价或板块关键数据缺失、延迟或不完整

### 7.2 配额建议

1. A 级：每日 3-8 只
2. B 级：每日 5-20 只
3. X 级：不限，需单独统计且不计入策略效果评估

## 8. 服务接口草案

1. `WeakToStrongCandidateBuilder`
   - 输入：`build(candidate_trade_date: date, confirm_trade_date?: date) -> List[Candidate]`
   - 输出字段必须包含：`candidate_type`、`rule_version`、`evidence_json`
2. `WeakToStrongAuctionService`
   - 输入：`confirm(confirm_trade_date: date, candidates: List[Candidate], auction_ticks: Any, plate_context: Any) -> List[AuctionSignal]`
   - 输出：确认信号列表（A/B/C/X）
3. `WeakToStrongAuctionScorer`
   - 输入：`score(candidate: Candidate, auction_slice: Any, plate_context: Any) -> ScoreBreakdown`
   - 输出：四维分 + 风险扣分 + 总分 + 数据状态
4. `WeakToStrongAlertService`
   - 输入：`render(signal: AuctionSignal) -> AlertMessage`
   - 输出：终端/Web/消息通知（A/B/C/X 统一模板）

## 9. 输出解释模板（统一）

每条信号必须提供：

1. 入选原因（命中项）
2. 扣分原因（风险项）
3. 关键证据（价格/量能/形态/联动）
4. 最终结论（A/B/C + 建议动作）

## 附录 A：评分细则（可执行草案）

## A.1 总分公式

`confirmation_score = price_strength + pattern_stability + last_minute_grab + plate_follow - risk_penalty`

其中：

1. `price_strength` ∈ [0, 30]
2. `pattern_stability` ∈ [0, 25]
3. `last_minute_grab` ∈ [0, 25]
4. `plate_follow` ∈ [0, 20]
5. `risk_penalty` ∈ [0, 30]

## A.2 分项细则

### A.2.1 价格强度（0-30）

1. 高开幅度位于候选预期区间：0-10
2. 是否站上昨日收盘/弱K实体上沿/关键承接位：0-10
3. 竞价尾值相对竞价均价强度：0-10

### A.2.2 形态稳定（0-25）

1. 9:20-9:25 波动稳定性：0-10
2. 尾段上翘/阶梯抬升/U形回拉质量：0-10
3. 急拉急砸异常控制：0-5（异常则不给分）

### A.2.3 最后一分钟抢筹（0-25）

1. 9:24-9:25 成交量相对前4分钟放大：0-10
2. 最后一分钟价格抬升（非回落）：0-10
3. 委买增强或承接增强：0-5

### A.2.4 板块联动（0-20）

1. 题材红盘率/强势率：0-8
2. 前排票同步强势：0-6
3. 核心票助攻与退潮抑制：0-6

## A.3 风险扣分（0-30）

1. 尾段急跌：0-12
2. 红盘失守：0-8
3. 冲高回落风险：0-6
4. 板块明显转弱：0-4

## A.4 数据质量状态规则

1. `ok`：关键窗口数据完整且时效正常
2. `partial`：存在非关键字段缺失，可降级评分
3. `delayed`：关键数据延迟，转 `X` 或仅观察
4. `missing`：关键窗口缺失，直接 `X`
