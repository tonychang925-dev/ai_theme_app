<span id="0-文档目的"></span>
## 0. 文档目的

本设计文档用于彻底修正当前"日采集控制台"和"当日复盘"之间职责混乱的问题，将系统拆分为两个清晰模块：

```text
模块一：采集模块
职责：每日基础数据采集
入口：日采集控制台

模块二：复盘模块
职责：每日动态复盘数据生成 + 复盘报告展示
入口：当日复盘页面
```

本次重构的核心目标不是继续修补某个空字段，而是恢复清晰的工程边界：

```text
采集模块只采集原材料
复盘模块负责加工每日动态结果
展示模块只展示复盘快照
```

<span id="1-当前问题复盘"></span>
## 1. 当前问题复盘

### 1.1 当前实际问题

1. 日采集控制台显示"完整执行"，但复盘报告大量字段为空
2. `subject_stock_daily_snapshot` 有 26K 数据，但复盘核心表为 0
3. 复盘页面缺失：主线与支线、主线资金流入前10、强势股分层、龙虎榜
4. `strong_stock_watch` 控制台任务是假成功
5. `recap_snapshot` 在真源表未准备好时仍写入空快照
6. 前端新增"主线与支线（结构化）"偏离 5/22 已验收样式

### 1.2 根因总结

```text
日采集控制台 ≠ 复盘数据完成
复盘快照生成 ≠ 真源表已就绪
控制台全绿 ≠ 复盘报告可展示
```

<span id="2-总体架构重构目标"></span>
## 2. 总体架构重构目标

### 2.1 新架构总览

```text
外部数据源 (JYHF / Tushare / 龙虎榜 / 竞价 / 原始异动)
        ↓
【模块一】采集模块（日采集控制台）
        ↓
基础数据表 / 原始数据表
        ↓
【模块二】复盘模块（当日复盘页面）
    阶段一：每日动态复盘数据生成
        ↓
    复盘真源表 / 派生结果表
        ↓
    阶段二：复盘报告展示
        ↓
post_market_recap_snapshot / DailyReview / 前端 5/22 样式展示
```

### 2.2 两个模块的边界

| 模块 | 页面入口 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 采集模块 | 日采集控制台 | 采集每日基础数据、原始数据、基础快照 | 不生成复盘报告、不负责题材周期结论、不负责最终复盘展示 |
| 复盘模块 | 当日复盘页面 | 生成每日动态复盘数据、生成复盘快照、展示复盘报告 | 不重新采集外部基础数据、不修改采集控制台逻辑 |

### 2.3 核心原则

1. 采集模块只做"原材料入库"
2. 复盘模块负责"基于原材料计算每日动态结果"
3. 复盘模块内部必须拆成两个阶段：阶段一（动态数据生成）、阶段二（报告展示）
4. read-only 只能用于已完成动态数据生成之后的重新封装/渲染
5. 不允许在真源数据不完整时写入成功快照
6. 前端展示样式必须保持 5/22 已验收版本

<span id="3-模块一采集模块设计"></span>
## 3. 模块一：采集模块设计

### 3.1 模块定位

采集模块沿用当前"日采集控制台"功能。职责：**把每日基础数据采集进数据库。**

采集模块不负责：题材周期判断、强势股分层计算、资金行为增强、复盘报告生成、DailyReview生成、前端复盘展示。

### 3.2 日采集控制台保留任务

| 任务 | 目标产物 | 说明 |
|------|---------|------|
| JYHF / 股票快照 | `subject_stock_daily_snapshot` | 题材列表、节点、详情、股票日快照 |
| Tushare 日K线 / 竞价 | `stock_daily_bar`, `auction_snapshot` | 基础行情数据 |
| 龙虎榜原始数据 | raw dragon tiger rows | 龙虎榜原始采集 |
| 异动股票基础数据 | abnormal raw inputs | 异动候选输入 |
| 龙头候选 LLM 裁决 | `leader_llm_queue/candidate` | LLM裁决输入与结果 |

### 3.3 采集模块不得出现的行为

1. 生成 `post_market_recap_snapshot`
2. 显示"复盘报告已生成"
3. 假成功（status=success 但目标表为空）
4. 把复盘真源计算藏在采集任务里
5. 直接触发 RecapPage 的复盘展示刷新

<span id="5-复盘模块阶段一每日动态复盘数据生成"></span>
## 5. 复盘模块阶段一：每日动态复盘数据生成

### 5.1 执行流程

```text
Step 0：基础采集数据 readiness 检查
Step 1：题材周期真源生成 (theme_cycle_truth)
Step 2：龙虎榜对象化 (dragon_tiger_object_build)
Step 3：资金行为增强 (money_flow_enhanced_build)
Step 4：强势股跟踪池生成 (strong_stock_watch_build)
Step 5：复盘真源 readiness 检查
```

### 5.2 目标产物与验收

| Step | 目标表 | 验收 SQL | 要求 |
|------|--------|---------|------|
| 1 | `theme_cycle_judgement_v2` | `select count(*) where trade_date=:d` | rows > 0 |
| 2 | `dragon_tiger_object` | `select count(*) where trade_date=:d` | rows > 0 或 skipped_no_data |
| 3 | `money_flow_enhanced` | `select count(*) where trade_date=:d` | rows > 0 |
| 4 | `strong_stock_watch_history` | `select count(*) where trade_date=:d` | rows > 0 |
| 5 | readiness check | 5表全部检查 | ready / failed_precondition |

<span id="6-复盘模块阶段二复盘报告展示"></span>
## 6. 复盘模块阶段二：复盘报告展示

阶段二才是 read-only。负责：读取复盘真源表 → 封装 DailyReview → 写入快照 → 前端 5/22 样式展示。

阶段二不负责：重新采集外部数据、重新计算题材周期/强势股分层/资金行为增强。

### 6.1 DailyReview 结构

```ts
interface DailyReview {
  review_date: string
  market_summary: MarketSummary
  theme_reviews: ThemeReview[]
  capital_reviews: CapitalReview[]
  strong_stock_reviews: StrongStockReview[]
  trading_principle: TradingPrinciple
  diagnostics: {
    snapshot_status: string
    readiness: object
    missing_sections: string[]
  }
  created_at: string
}
```

### 6.2 ThemeReview 字段（含 5/22 兼容字段）

```ts
interface ThemeReview {
  subject_key: string; theme_name: string;
  theme_stage: string; theme_strength?: string;
  // 5/22 页面兼容字段
  theme_kline?: string; event_score?: number; market_score?: number;
  mainline_strength_score: number; fade_risk_score: number;
  final_cycle_state: string; final_mainline_alive: boolean;
  total_inflow?: number; leader_inflow?: number;
  capital_validation?: string; leader_stocks: LeaderStockBrief[];
  event_chain: ThemeEventItem[];
  action_advice: string; conclusion: string;
}
```

### 6.3 StrongStockReview 字段

```ts
interface StrongStockReview {
  stock_code: string; stock_name: string;
  theme_name: string; subject_key: string; role: string;
  leader_composite_score: number; leader_capital_score: number;
  trend_strength_score: number; support_score: number;
  position_label: string; pattern_labels: string[];
  pct_chg: number; turnover_rate: number; volume_ratio: number;
```

<span id="12-状态机设计"></span>
## 12. 状态机设计

```text
NOT_COLLECTED → BASE_READY → DERIVING → DERIVED_READY → RECAP_GENERATING → RECAP_READY
                                         ↘ FAILED_PRECONDITION
                                         ↘ FAILED
```

新增 `post_market_job_status` 表：

```sql
create table if not exists post_market_job_status (
    id bigserial primary key,
    trade_date date not null,
    job_key text not null,
    status text not null,
    started_at timestamptz,
    finished_at timestamptz,
    error_code text,
    error_message text,
    diagnostics jsonb default '{}'::jsonb,
    created_at timestamptz default now(),
    updated_at timestamptz default now(),
    unique (trade_date, job_key)
);
```

<span id="13-错误处理规则"></span>
## 13. 错误处理规则

1. **不允许假成功**：目标表 rows=0 时，状态必须是 `skipped_no_data` / `failed_no_rows` / `failed_precondition`
2. **不允许覆盖完整快照**：readiness 不通过时，不允许写 `post_market_recap_snapshot`
3. **partial 明确化**：部分生成必须在 diagnostics 中记录 `missing_sections`

<span id="14-验收标准"></span>
## 14. 验收标准

### 14.1 日采集控制台验收

```sql
select count(*) from subject_stock_daily_snapshot where trade_date=:d;  -- rows > 0
```

### 14.2 动态数据生成验收

```sql
select count(*) from theme_cycle_judgement_v2 where trade_date=:d;     -- > 0
select count(*) from money_flow_enhanced where trade_date=:d;          -- > 0
select count(*) from strong_stock_watch_history where trade_date=:d;   -- > 0
select count(*) from dragon_tiger_object where trade_date=:d;          -- > 0 或 skipped
```

### 14.3 复盘报告生成验收

```text
readiness ready
post_market_recap_snapshot affected_rows = 1
snapshot_status = complete
```

### 14.4 前端页面验收

主线与支线 / 主线资金流入前10 / 强势股分层 / 龙虎榜 四栏目有数据或明确无数据。页面样式与 5/22 一致。不显示"主线与支线（结构化）"。
