# 选股器功能详细设计规范

## 1. 概述

### 1.1 设计背景
基于交易体系中的35%/30%/20%/15%决策序列，构建系统化的选股器功能，帮助用户从AI分析结果中筛选出符合交易逻辑的股票。

### 1.2 核心决策序列
- **35%**: 主线题材判断 - 基于`theme_mainline_judgement`表
- **30%**: 周期阶段判断 - 基于`theme_cycle_judgement_v2`表  
- **20%**: 龙头判断 - 基于`theme_leader_candidate`表
- **15%**: 技术面验证 - 基于股票异动标记系统

### 1.3 功能定位
- 作为投研工作台的增强功能，提供系统化选股能力
- 与现有题材雷达、AI事件流、行情验证三栏布局协同工作
- 支持自定义筛选策略和结果导出
- 支持规则选股后的LLM二次复核（复用“强势股分层”既有LLM复核模块）

## 2. 数据模型设计

### 2.1 核心数据表扩展

#### 2.1.1 选股策略表 (stock_screening_strategy)
```sql
CREATE TABLE stock_screening_strategy (
    strategy_id VARCHAR(64) PRIMARY KEY,
    strategy_name VARCHAR(128) NOT NULL,
    strategy_type VARCHAR(32) NOT NULL, -- 'mainline', 'cycle', 'leader', 'technical', 'composite'
    description TEXT,
    weight_config JSONB NOT NULL, -- 权重配置 {mainline: 0.35, cycle: 0.30, leader: 0.20, technical: 0.15}
    filter_config JSONB NOT NULL, -- 筛选条件配置
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    created_by VARCHAR(64),
    is_active BOOLEAN DEFAULT TRUE
);
```

#### 2.1.2 选股结果表 (stock_screening_result)
```sql
CREATE TABLE stock_screening_result (
    result_id VARCHAR(64) PRIMARY KEY,
    strategy_id VARCHAR(64) NOT NULL REFERENCES stock_screening_strategy(strategy_id),
    trade_date DATE NOT NULL,
    stock_id VARCHAR(32) NOT NULL,
    stock_name VARCHAR(64),
    composite_score DECIMAL(5,2) NOT NULL, -- 综合得分 (0-100)
    dimension_scores JSONB NOT NULL, -- 各维度得分 {mainline: 85, cycle: 72, leader: 90, technical: 65}
    dimension_details JSONB NOT NULL, -- 各维度详情
    rank_position INTEGER, -- 排名位置
    screening_reason TEXT, -- 筛选理由
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    INDEX idx_trade_date_strategy (trade_date, strategy_id),
    INDEX idx_stock_score (stock_id, composite_score DESC)
);
```

#### 2.1.3 用户选股收藏表 (user_stock_screening_favorite)
```sql
CREATE TABLE user_stock_screening_favorite (
    favorite_id VARCHAR(64) PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    result_id VARCHAR(64) NOT NULL REFERENCES stock_screening_result(result_id),
    notes TEXT,
    tags JSONB, -- 用户自定义标签
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(user_id, result_id)
);
```

#### 2.1.4 选股LLM复核结果表 (stock_screening_llm_review)
```sql
CREATE TABLE stock_screening_llm_review (
    review_id VARCHAR(64) PRIMARY KEY,
    execution_id VARCHAR(64) NOT NULL,
    strategy_id VARCHAR(64) NOT NULL REFERENCES stock_screening_strategy(strategy_id),
    trade_date DATE NOT NULL,
    result_id VARCHAR(64) NOT NULL REFERENCES stock_screening_result(result_id),
    stock_id VARCHAR(32) NOT NULL,
    decision VARCHAR(16) NOT NULL, -- pass/watch/reject/failed
    llm_score DECIMAL(6,2),
    confidence DECIMAL(4,3),
    reasoning TEXT,
    risk_flags JSONB NOT NULL DEFAULT '[]'::jsonb,
    evidence_refs JSONB NOT NULL DEFAULT '[]'::jsonb,
    model_name VARCHAR(64),
    prompt_version VARCHAR(64) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_stock_screening_llm_review_result_id ON stock_screening_llm_review(result_id);
CREATE INDEX idx_stock_screening_llm_review_exec ON stock_screening_llm_review(execution_id, trade_date);
```

### 4.6 状态与异常态设计
- `isExecuting=true`：执行按钮禁用，显示进度文案“正在执行选股...”
- `llm_review_status=skipped_no_api_key`：顶部黄色提示“未配置DEEPSEEK_API_KEY，已跳过LLM复核”
- `llm_review_status=partial_failed`：顶部橙色提示“部分复核失败，规则结果仍可用”
- 空结果态：展示“无符合条件标的”，提供“降低min_score”快捷按钮
- 网络失败态：显示重试按钮，并保留上次结果快照
