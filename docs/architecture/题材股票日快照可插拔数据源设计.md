# 题材股票日快照 — 可插拔数据源方案设计

> 版本: 1.2 | 日期: 2026-06-08 | 状态: 后端 P0 实现完成，待前端 UI
> 核心决策: subject_stock_daily_snapshot 保持唯一标准输出表，生产方式通过配置切换
> 修订: v1.1 补强 5 点 / v1.2 后端 P0 代码落地 + 测试验证通过

## 一、设计目标

保留同一个目标表、同一个下游消费接口，只把 `subject_stock_daily_snapshot` 的生产者做成可配置。

```
JYHF Producer          ┐
                       ├── subject_stock_daily_snapshot  (唯一标准输出)
TushareJoin Producer   ┘
```

- 同一张表
- 同一套字段
- 同一套下游消费逻辑
- 不同的数据生产者
- 通过配置切换，默认 `jyhf`

## 二、配置设计

### 2.1 配置文件

```yaml
collection:
  stock_snapshot:
    provider: jyhf        # 默认 jyhf，可选 jyhf / tushare_join
    on_existing: skip     # skip / upsert / replace
    enable_quality_check: true

    jyhf:
      enabled: true
      sync_theme_list: false     # 题材库已本地化，无需每日同步
      load_staging: false        # 同上
      import_stock_daily: true

    tushare_join:
      enabled: true
      require_daily_bar: true
      auto_run_daily_bar: false
      rank_method: pct_chg_desc
      stock_id_format: local_6digit
      limit_up_rule: pct_chg_9_8
```

### 2.2 环境变量

```bash
STOCK_SNAPSHOT_PROVIDER=jyhf            # 默认 JYHF
# STOCK_SNAPSHOT_PROVIDER=tushare_join  # 切换到 Tushare 拼接
```

### 2.3 on_existing 策略

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| `skip` | 当日已有数据则跳过 | 默认生产环境 |
| `upsert` | 按当前 provider 覆盖已有行 | 切换模式后重新生成 |
| `replace` | 先删当日全部数据再完整重建 | 数据修复/强制重建 |

默认: `skip`，手动重跑: `replace`。

## 四、Producer 接口设计

### 4.1 统一协议

```python
# stock_processing_service/application/jobs/subject_stock_snapshot/base.py

from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from datetime import date
from typing import Any


@dataclass
class SubjectStockSnapshotBuildRequest:
    trade_date: date
    force: bool = False
    batch_id: str | None = None
    provider: str = "jyhf"
    on_existing: str = "skip"   # skip / upsert / replace

    # force 与 on_existing 优先级:
    #   force=false + on_existing=skip     → 已有则跳过
    #   force=false + on_existing=upsert   → 已有则覆盖
    #   force=false + on_existing=replace  → 先删再重建
    #   force=true                         → 等价于 on_existing=replace


@dataclass
class SubjectStockSnapshotBuildResult:
    provider: str
    trade_date: str
    status: str
    affected_rows: int
    warnings: list[str] = field(default_factory=list)
    metrics: dict[str, Any] = field(default_factory=dict)


class SubjectStockDailySnapshotProducer(ABC):
    @abstractmethod
    async def build(
        self,
        request: SubjectStockSnapshotBuildRequest,
    ) -> SubjectStockSnapshotBuildResult:
        ...
```

### 4.2 目录结构

```
stock_processing_service/
  application/

        __init__.py
        base.py                   ← 统一协议

        tushare_join_producer.py  ← Tushare Join Producer（新增）
```

## 五、JYHF Producer（默认）

包装已有的 `jyhf.import_stock_daily`，不重写现有逻辑。

```python
# jyhf_producer.py

class JyhfSubjectStockDailySnapshotProducer(SubjectStockDailySnapshotProducer):
    provider = "jyhf"

    def __init__(self, jyhf_import_job, db_pool):
        self._jyhf_import_job = jyhf_import_job
        self._db_pool = db_pool

    async def build(self, request: SubjectStockSnapshotBuildRequest):
        batch_id = request.batch_id or f"jyhf_stock_daily_{request.trade_date:%Y%m%d}"

        result = await self._jyhf_import_job.execute(
            trade_date=request.trade_date,
            force=request.force,
            batch_id=batch_id,
        )

        return SubjectStockSnapshotBuildResult(
            provider="jyhf",
            trade_date=str(request.trade_date),
            status=result.status,
            affected_rows=result.affected_rows,
            warnings=getattr(result, "warnings", []),
            metrics={
                "source": "jyhf_api",
                "batch_id": batch_id,
            },
        )
```

JYHF 方式保持现状:
- 遍历 subject_key
- 调用 JYHF API `stock/realtime-by-subject/v2`
- 写入 `subject_stock_daily_snapshot`

## 六、Tushare Join Producer

依赖 `stock_daily_snapshot` (已由 `tushare.daily_bar` 写入) + `subject_stock_map` (本地静态映射)。

### 6.1 流程

```
1. 检查 stock_daily_snapshot 是否已有当日 Tushare 日K
2. 检查 subject_stock_map 是否有映射数据
3. 根据 on_existing 配置处理已有 subject_stock_daily_snapshot
4. 执行 JOIN 拼接（stock_daily_snapshot + subject_stock_map）
5. 自算 rank_order (题材内 pct_chg DESC)
6. 写入 raw_json / ingest_batch_id 标记来源
7. 输出质量报告
```

### 6.2 核心 SQL

```sql
INSERT INTO subject_stock_daily_snapshot (
    trade_date,
    subject_key,
    stock_id,
    stock_name,
    open_price,
    high_price,
    low_price,
    close_price,
    pre_close,
    pct_chg,
    volume,
    amount,
    rank_order,
    is_leader,
    limit_up,
    raw_json,
    ingest_batch_id
)
SELECT
    sds.trade_date,
    ssm.subject_key,
    ssm.stock_id,
    COALESCE(ssm.name, sds.stock_name) AS stock_name,

    sds.open_price,
    sds.high_price,
    sds.low_price,
    sds.close_price,
    sds.pre_close,
    sds.pct_chg,
    sds.volume,
    sds.amount,

    ROW_NUMBER() OVER (
        PARTITION BY ssm.subject_key
        ORDER BY COALESCE(sds.pct_chg, -999) DESC,
                 COALESCE(sds.amount, 0) DESC
    ) AS rank_order,

    COALESCE(ssm.top, FALSE) AS is_leader,

    CASE
        WHEN COALESCE(sds.pct_chg, 0) >= 9.8 THEN TRUE
        ELSE FALSE
    END AS limit_up,

    jsonb_build_object(
        'snapshot_provider', 'tushare_join',
        'source', 'stock_daily_snapshot + subject_stock_map',
        'subject_stock_map_source_type', ssm.source_type,
        'map_evidence', ssm.evidence_json,
        'tushare_stock_id', sds.stock_id,
        'local_stock_id', ssm.stock_id
    ) AS raw_json,

    $2::varchar AS ingest_batch_id

FROM subject_stock_map ssm
JOIN stock_daily_snapshot sds
  ON sds.trade_date = $1::date
 AND SPLIT_PART(sds.stock_id, '.', 1) = ssm.stock_id

WHERE ssm.stock_id IS NOT NULL
  AND ssm.stock_id <> ''

ON CONFLICT (trade_date, subject_key, stock_id)
DO UPDATE SET
    stock_name = EXCLUDED.stock_name,
    open_price = EXCLUDED.open_price,
    high_price = EXCLUDED.high_price,
    low_price = EXCLUDED.low_price,
    close_price = EXCLUDED.close_price,
    pre_close = EXCLUDED.pre_close,
    pct_chg = EXCLUDED.pct_chg,
    volume = EXCLUDED.volume,
    amount = EXCLUDED.amount,
    rank_order = EXCLUDED.rank_order,
    is_leader = EXCLUDED.is_leader,
    limit_up = EXCLUDED.limit_up,
    raw_json = EXCLUDED.raw_json,
    ingest_batch_id = EXCLUDED.ingest_batch_id,
    updated_at = NOW();
```

**stock_id 匹配**: `SPLIT_PART(sds.stock_id, '.', 1) = ssm.stock_id`（Tushare `000001.SZ` → JYHF `000001`）

## 七、统一 Orchestrator

```python
# orchestrator.py

class SubjectStockDailySnapshotOrchestrator:
    """统一入口：根据配置选择 Producer 并执行，前端不直接感知具体 Producer。"""

    def __init__(self, config, producer_factory, db_pool):
        self._config = config
        self._producer_factory = producer_factory
        self._db_pool = db_pool

    async def execute(
        self,
        trade_date: date,
        provider: str | None = None,
        force: bool = False,
        on_existing: str | None = None,
    ) -> SubjectStockSnapshotBuildResult:
        selected_provider = (
            provider
            or self._config.collection.stock_snapshot.provider
            or "jyhf"
        )
        resolved_on_existing = (
            on_existing
            or self._config.collection.stock_snapshot.on_existing
            or "skip"
        )
        # force=true 等价于 replace
        if force:
            resolved_on_existing = "replace"

        producer = self._producer_factory.get(selected_provider)
        batch_id = f"{selected_provider}_subject_stock_daily_{trade_date:%Y%m%d}"

        request = SubjectStockSnapshotBuildRequest(
            trade_date=trade_date,
            provider=selected_provider,
            force=force,
            on_existing=resolved_on_existing,
            batch_id=batch_id,
        )

        result = await producer.build(request)
        await self._record_run(request, result)
        return result

    async def _record_run(self, request: SubjectStockSnapshotBuildRequest, result: SubjectStockSnapshotBuildResult):
        """写入 subject_stock_daily_snapshot_build_run 审计表。
        记录 provider / on_existing / force 等关键决策参数。
        """
        ...
```

### Factory

```python
# factory.py

class SubjectStockSnapshotProducerFactory:
    def __init__(self, jyhf_producer, tushare_join_producer):
        self._producers = {
            "jyhf": jyhf_producer,
            "tushare_join": tushare_join_producer,
        }

    def get(self, provider: str) -> SubjectStockDailySnapshotProducer:
        if provider not in self._producers:
            raise ValueError(
                f"unsupported subject_stock_daily_snapshot provider: {provider}"
            )
        return self._producers[provider]
```

## 八、数据冲突策略

同一个交易日、同一个题材、同一只股票只能有一条权威数据。

### 8.1 skip（默认）

如果当日已有数据，直接跳过。适合默认生产环境。

### 8.2 upsert

按当前 provider 覆盖已有行。适合切换模式后重新生成。

### 8.3 replace

先删除当日数据，再完整重建。适合数据修复。

```sql
DELETE FROM subject_stock_daily_snapshot WHERE trade_date = $1;
```

推荐: 默认 `skip`，手动重跑时 `replace`。

## 九、运行审计表

为了追踪某天的数据到底是 JYHF 生成还是 Tushare Join 生成：

```sql
CREATE TABLE IF NOT EXISTS subject_stock_daily_snapshot_build_run (
    id BIGSERIAL PRIMARY KEY,
    trade_date DATE NOT NULL,
    provider VARCHAR(32) NOT NULL,
    batch_id VARCHAR(128) NOT NULL,
    status VARCHAR(32) NOT NULL,
    affected_rows INTEGER NOT NULL DEFAULT 0,

    on_existing VARCHAR(16) NOT NULL DEFAULT 'skip',
    force_mode BOOLEAN NOT NULL DEFAULT FALSE,

    stock_daily_count INTEGER,
    mapped_stock_count INTEGER,
    matched_stock_count INTEGER,
    missing_stock_count INTEGER,
    subject_count INTEGER,
    covered_subject_count INTEGER,
    coverage_pct NUMERIC(8, 4),

    config_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    metrics_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    warnings_json JSONB NOT NULL DEFAULT '[]'::jsonb,

    started_at TIMESTAMP NOT NULL DEFAULT NOW(),
    finished_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_subject_stock_snapshot_build_run_date
ON subject_stock_daily_snapshot_build_run (trade_date);

CREATE INDEX IF NOT EXISTS idx_subject_stock_snapshot_build_run_provider
ON subject_stock_daily_snapshot_build_run (provider);
```

`config_json` 示例：

```json
{
  "provider": "tushare_join",
  "on_existing": "replace",
  "force": true,
  "rank_method": "pct_chg_desc",
  "limit_up_rule": "pct_chg_9_8"
}
```

主表不需要额外加 `provider` 列:
- 主表负责服务下游
- build_run 表负责审计来源（含 provider / on_existing / force）
- raw_json / ingest_batch_id 负责单行追踪

### 实施前核查：主表唯一索引

Tushare Join SQL 使用 `ON CONFLICT (trade_date, subject_key, stock_id)`，必须确认该约束存在：

```sql
-- 核查是否已有唯一约束
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'subject_stock_daily_snapshot'
  AND indexdef ILIKE '%unique%';

-- 如不存在则创建
CREATE UNIQUE INDEX IF NOT EXISTS ux_subject_stock_daily_snapshot_date_subject_stock
ON subject_stock_daily_snapshot (trade_date, subject_key, stock_id);
```

如果表已有等价的 UNIQUE CONSTRAINT 则无需重复创建，但实施前须通过上述 SQL 核查确认。

## 十、质量检查

无论 JYHF 还是 Tushare Join，统一输出质量报告。

### Tushare Join 模式检查

```sql
-- 1. Tushare 当日股票数
SELECT COUNT(*) AS stock_daily_count
FROM stock_daily_snapshot WHERE trade_date = $1;

-- 2. 本地映射股票数
SELECT COUNT(DISTINCT stock_id) AS mapped_stock_count
FROM subject_stock_map
WHERE stock_id IS NOT NULL AND stock_id <> '';

-- 3. 成功匹配股票数
SELECT COUNT(DISTINCT ssm.stock_id) AS matched_stock_count
FROM subject_stock_map ssm
JOIN stock_daily_snapshot sds
  ON sds.trade_date = $1
 AND SPLIT_PART(sds.stock_id, '.', 1) = ssm.stock_id
WHERE ssm.stock_id IS NOT NULL AND ssm.stock_id <> '';

-- 4. 缺失股票清单
SELECT DISTINCT
    ssm.stock_id,
    ssm.name,
    COUNT(DISTINCT ssm.subject_key) AS subject_count
FROM subject_stock_map ssm
LEFT JOIN stock_daily_snapshot sds
  ON sds.trade_date = $1
 AND SPLIT_PART(sds.stock_id, '.', 1) = ssm.stock_id
WHERE ssm.stock_id IS NOT NULL AND ssm.stock_id <> ''
  AND sds.stock_id IS NULL
GROUP BY ssm.stock_id, ssm.name
ORDER BY subject_count DESC, ssm.stock_id;
```

## 十一、兼容规则

两种模式必须统一以下规则：

| 规则 | JYHF 模式 | Tushare Join 模式 |
|------|----------|-------------------|
| stock_id 格式 | 无后缀 `000001` | 无后缀 `000001` |
| rank_order | JYHF API 返回的排名 | `ROW_NUMBER() OVER subject_key ORDER BY pct_chg DESC` |
| is_leader | 原始数据龙头标记 | `subject_stock_map.top` |
| limit_up | `pct_chg >= 9.8` | `pct_chg >= 9.8` |
| raw_json.snapshot_provider | `"jyhf"` | `"tushare_join"` |
| ingest_batch_id | `jyhf_subject_stock_daily_{date}` | `tushare_join_subject_stock_daily_{date}` |

## 十三、任务编排

### 默认模式 (JYHF)

```
stock_snapshot.build (provider=jyhf)
  1. jyhf.sync_lists          (可选，默认 false)
  2. jyhf.load_staging        (可选，默认 false)
  3. 根据 on_existing 处理已有数据 (skip/upsert/replace)
  4. jyhf.import_stock_daily
  5. quality_check
  6. record_build_run (含 on_existing / force)
```

### Tushare Join 模式

```
stock_snapshot.build (provider=tushare_join)
  1. 检查 stock_daily_snapshot 是否存在
  2. 如 auto_run_daily_bar=true，先执行 tushare.daily_bar
  3. 根据 on_existing 处理已有数据 (skip/upsert/replace)
  4. JOIN subject_stock_map + stock_daily_snapshot
  5. 写入 subject_stock_daily_snapshot
  6. quality_check
  7. record_build_run (含 on_existing / force)
```

## 十六、结论

最终效果:

- **默认**: `provider=jyhf` → 走久赢恒丰采集 `subject_stock_daily_snapshot`
- **切换**: `provider=tushare_join` → 走 Tushare 日K + subject_stock_map 拼接
- **下游**: 完全不改，仍然只读 `subject_stock_daily_snapshot`

这既保留了当前 JYHF 链路的稳定性，也为后续逐步脱离 JYHF 留好了接口。当前阶段建议默认仍是 `jyhf`，在采集控制台加一个可选切换项「Tushare 日K拼接生成」用于日线复盘链路验证。
