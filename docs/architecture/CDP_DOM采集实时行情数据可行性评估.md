# CDP DOM 采集实时行情数据 — 可行性评估

> 日期: 2026-05-25
> 评估范围: 通过 CDP DOM 方式从久赢恒丰 App 采集实时行情数据（分钟级走势、竞价数据、资金流向、股价、成交量等）

---

## 一、结论

**不建议实施。** CDP DOM 方式不适合实时行情数据采集，原因如下：

1. **时序精度不足** — CDP 轮询间隔（20s）远超行情数据要求的秒级/分钟级粒度
2. **Canvas 图表数据不可达** — K线/分时图通过 Canvas 渲染，无法从 DOM 文本提取
3. **系统已有更优替代方案** — akshare 可直接获取交易所/财经网站的实时行情，无需经过久赢恒丰 DOM 层
4. **稳健性风险** — JYHF App 网络波动直接阻断数据采集

以下逐项分析。

---

## 二、逐类可行性分析

### 2.1 分钟级行情走势

**JYHF 展示方式**: K线图（Canvas 渲染）+ 分时图（Canvas 渲染）

| 维度 | 评估 |
|------|------|
| 数据存在性 | ✅ JYHF App 内部持有 OHLCV 数组数据（JS 内存） |
| DOM 文本提取 | ❌ Canvas 位图，无文本可提取 |
| JS 内存提取 | ⚠️ 理论上可通过 CDP evaluate 读取 Vue 组件 data 属性，但需逆向 Vue 组件树结构 |
| 轮询频率 | ❌ 分钟线需要 ≤60s 采集间隔，当前 CDP 设计为 20s 间隔，持续高频 CDP 调用会影响 JYHF App 性能 |
| 已有替代方案 | ✅ `akshare.stock_zh_a_hist()` 可获取历史 K 线，易得且不依赖 JYHF |

**结论: 不可行。** Canvas 渲染阻断了 DOM 文本提取路径；JS 内存提取需逆向组件树且不稳定。

### 2.2 早盘/尾盘竞价数据

**JYHF 展示方式**: 表格/列表（竞价价格、成交量、未匹配量）

| 维度 | 评估 |
|------|------|
| 数据存在性 | ✅ JYHF 盘前必读/竞价页面展示 |
| DOM 文本提取 | ✅ 表格文本可提取 |
| 时序精度 | ❌ 竞价阶段（9:15-9:25）数据秒级变化，需 ≤3s 轮询才能捕捉关键价格节点 |
| 可靠性 | ❌ 竞价窗口仅 10 分钟，JYHF App 启动/CDP 连接/页面导航需 15-30s，极易错过关键时点 |
| 已有替代方案 | ✅ 系统现有 `database_service.gateway` 已接入竞价数据，`akshare.stock_zh_a_tick_tx()` 可获取逐笔数据 |

**结论: 不可行。** CDP 轮询频率和启动延迟无法满足竞价数据的时序要求。

### 2.3 资金流向数据（主力净流入/流出）

**JYHF 展示方式**: 文本数值（如"主力净流入 1.23 亿"）

| 维度 | 评估 |
|------|------|
| 数据存在性 | ✅ JYHF App 个股详情页展示 |
| DOM 文本提取 | ✅ 数值文本可提取 |
| 批量采集 | ❌ 需逐只股票导航才能获取，A 股 5000+ 只，无法批量采集 |
| 数据颗粒度 | ⚠️ JYHF 展示的是聚合数据（日级），非实时分钟级 |
| 已有替代方案 | ✅ `akshare.stock_individual_fund_flow()` 可直接获取个股资金流向 |

**结论: 不可行。** 批量采集需逐只股票页面导航，5000+ 只股票无法规模化。

### 2.4 实时股价与成交量

**JYHF 展示方式**: 文本数值（如"¥12.34 +5.2% 成交量 1.23亿"）

| 维度 | 评估 |
|------|------|
| 数据存在性 | ✅ JYHF 行情报价页/自选股页展示 |
| DOM 文本提取 | ✅ 数值文本可提取 |
| 延迟 | ⚠️ CDP 轮询 20s + JYHF 自身数据刷新延迟，总延迟可能 30s+ |
| 覆盖范围 | ⚠️ 仅能采集当前页面可见的股票（自选股或当前浏览页） |
| 已有替代方案 | ✅ `akshare.stock_zh_a_spot_em()` 可获取全市场实时行情，延迟更低 |

**结论: 技术上可行但不建议。** 已有更优替代方案（akshare 直连交易所数据源），延迟更低、覆盖更全、不依赖 JYHF App。

## 三、技术障碍清单

| # | 障碍 | 严重度 | 说明 |
|---|------|--------|------|
| 1 | Canvas 图表不可文本提取 | 致命 | K线图、分时图均为 Canvas 渲染，`innerText` 无法读取 |
| 2 | CDP 轮询频率上限 | 致命 | 20s 间隔对实时行情（1min/5min/竞价）完全不够 |
| 3 | 批量采集不可行 | 致命 | 个股资金/价格需逐只导航，5000+ 股票无法规模化 |
| 4 | 网络依赖 | 高 | JYHF App 后端 API 不稳定时会丢失数据（当前已验证有超时） |
| 5 | Vue 组件逆向脆弱 | 高 | JS 内存提取依赖 Vue 组件内部结构，JYHF 更新即可能失效 |
| 6 | App 性能影响 | 中 | 高频 CDP evaluate 会增加 JYHF App JS 线程负载 |

---

## 四、推荐替代方案

| 数据需求 | 推荐方式 | 接口/工具 |
|---------|---------|----------|
| 分钟级 K 线 | akshare 直连 | `akshare.stock_zh_a_hist()` 或东方财富 API |
| 实时股价 | akshare 直连 | `akshare.stock_zh_a_spot_em()` |
| 竞价数据 | akshare + 交易所接口 | `akshare.stock_zh_a_tick_tx()` |
| 资金流向 | akshare / 东方财富 | `akshare.stock_individual_fund_flow()` |
| 成交量 | akshare 直连 | 同上实时行情接口 |

**均为系统已有集成方案**，无需额外开发 CDP 提取逻辑。

---

## 五、CDP DOM 采集的适当场景

CDP DOM 方式仍适用于以下场景（当前已实现）：

| 场景 | 原因 |
|------|------|
| ✅ 新事件题材发现 | 久赢恒丰独有的结构化分析结果，无可替代数据源 |
| ✅ 题材驱动事件提取 | 久赢恒丰 AI 聚合的事件文本，其他数据源无等效内容 |
| ✅ 盘前必读/复盘摘要 | 久赢恒丰 AI 生成的文本摘要 |

CDP DOM 的**核心价值在于采集久赢恒丰独有的 AI 分析内容**（文本/结构化事件），而非替代已有的行情数据基础设施。
