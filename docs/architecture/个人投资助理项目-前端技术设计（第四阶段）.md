# 个人投资助理项目-前端技术设计（第四阶段）

> 本说明书用于指导 **AI 投资个人助理（AI Agent）系统** 的前端设计与实现，参考「久赢恒丰」成熟投研界面，目标是构建一个 **桌面级、专业化、以 AI 认知为核心的投研工作台**。

---

## 一、设计目标与总体原则

### 1.1 产品目标

- 构建一个面向 **中高频投资者 / 研究型交易者** 的前端系统
- 将 **AI 事件理解能力** 以高密度、低噪音的方式呈现
- 支持从「题材发现 → 逻辑理解 → 行情验证 → 决策跟踪」的完整闭环

### 1.2 设计原则

1. **信息密度优先**：牺牲部分美观，换取决策效率
2. **结构即认知**：界面结构直接反映投资思考路径
3. **AI 为主，人为辅**：前端围绕 AI 输出组织，而非手工筛选
4. **强一致性**：前端组件结构与后端数据模型一一对应

---

## 二、整体前端架构设计

### 2.1 总体界面范式

采用三栏式「投研作战台」布局：

```
┌──────────┬────────────────────────┬──────────────┐
│ 题材雷达区 │ AI 事件理解与解读区     │ 行情验证区    │
│ (左栏)     │ (中栏)                 │ (右栏)        │
└──────────┴────────────────────────┴──────────────┘
```

### 2.2 逻辑分区职责

| 区域 | 核心职责 | 对应后端模块 |
|----|----|----|
| 左栏 | 决策入口 / 题材选择 | theme_service |
| 中栏 | 逻辑理解 / AI 解读 | model_service |
| 右栏 | 市场验证 / 行情反馈 | market_data_service |

---

## 三、技术方案选型

### 3.1 技术栈建议

| 层级 | 技术方案 | 说明 |
|----|----|----|
| 框架 | React 18 + TypeScript | 复杂状态管理、长期可维护 |

## 四、核心功能模块设计

### 4.1 左栏：题材雷达模块（Theme Radar）

#### 4.1.1 功能说明

- 展示 AI 聚合后的题材榜单
- 支持多维榜单切换（挖掘 / 涨停 / 涨幅）
- 作为全局上下文切换入口

#### 4.1.2 数据结构（前端 DTO）

```ts
interface ThemeItem {
  theme_id: string
  theme_name: string
  rank: number
  hit_count_day: number
  change_percent: number
  confidence: number
}
```

#### 4.1.3 交互逻辑

- 点击题材 → 更新当前全局选中 theme_id
- 触发中栏事件流 + 右栏行情刷新

---

### 4.2 中栏：AI 事件理解流（AI Event Feed）

#### 4.2.1 功能定位

- 系统“智能核心输出区”
- 用时间轴方式呈现 AI 对市场的持续理解

#### 4.2.2 事件类型设计

| event_type | 含义 |
|----|----|
| BREAKING | 新事件 / 突发 |
| MORNING | 盘前必读 |
| REVIEW | 热点复盘 |
| LIMIT_CHAIN | 连板/资金行为 |

#### 4.2.3 数据结构

```ts
interface AIEvent {
  event_id: string
  theme_id: string
  event_type: string
  event_time: string
  title: string
  ai_summary: string
  impact_score: number
}
```

#### 4.2.4 设计要点

- 强调 **结论句、数据、逻辑链** 的视觉突出
- 文本结构来源于 AI，而非前端二次解析

---

### 4.3 右栏：行情验证模块（Market Validation）

#### 4.3.1 功能说明

- 显示与当前题材 / 股票相关的行情走势
- 用于验证逻辑是否被价格确认

#### 4.3.2 功能组成

- 日线 / 周线 / 月线
- MA / VOL / MACD / KDJ

#### 4.3.3 设计原则

- 被动刷新
- 无复杂交互
- 服务于“理性制动”

## 八、每日复盘模块（Daily Review）设计

> 每日复盘是连接 **短期行情波动** 与 **中期题材演化** 的关键模块，是 AI Agent 从“实时判断”走向“策略沉淀”的核心功能。

---

### 8.1 功能定位

每日复盘 ≠ 新闻汇总，而是：

> **对“当天市场发生了什么、哪些逻辑被验证、哪些逻辑失效”的结构化总结。**

其核心价值在于：
- 帮助用户形成连续的市场记忆
- 为后续交易日提供明确的关注方向与操作纪律
- 为 AI 系统沉淀“题材生命周期数据”

---

### 8.2 页面结构设计（页面级）

建议每日复盘作为 **独立一级页面**，同时支持在「题材库」中被引用。

```
┌──────────────────────────────────────┐
│ 日期选择 / 今日总览                  │
├──────────────────────────────────────┤
│ 一、当前主要题材（核心）             │
│   - 题材A（事件链 + 情绪判定）       │
│   - 题材B                            │
│   - 题材C                            │
├──────────────────────────────────────┤
│ 二、龙虎榜 / 资金行为                │
├──────────────────────────────────────┤
│ 三、操作原则与交易纪律               │
└──────────────────────────────────────┘
```

---

### 8.3 模块一：当前主要题材（核心模块）

#### 8.3.1 设计思想

该模块用于回答一个核心问题：

> **“今天市场围绕哪些题材在博弈？这些题材的逻辑是否仍在增强？”**

#### 8.3.2 题材复盘结构

每一个题材作为一个 **ThemeReviewCard**：

- 题材名称
- 题材阶段（启动 / 加速 / 高位 / 衰退）
- 当日整体表现（涨幅 / 强度）
- 事件链（按时间排序）
- 情绪与资金判定
- 强势股跟踪入口

#### 8.3.3 事件链设计（关键）

事件链不是普通列表，而是 **“逻辑递进序列”**：

```ts
interface ThemeEvent {
  event_id: string
  event_date: string
  title: string
  description: string
  event_type: 'POLICY' | 'INDUSTRY' | 'COMPANY' | 'OVERSEAS'
  verified: boolean
}
```

前端呈现要点：
- 自动编号（事件1、2、3…）
- 支持跨日引用（历史事件不会消失）
- 明确区分【国内 / 海外 / 传闻】

---

### 8.4 模块二：龙虎榜与资金行为

#### 8.4.1 功能定位

用于验证：
> **“逻辑之外，资金是否真的在进场？”**

#### 8.4.2 展示方式

- 支持表格 + 图像混合
- 按：
  - 净买入金额
  - 机构 / 游资属性
  - 连续上榜天数

```ts
interface DragonTigerItem {
  stock_code: string
  stock_name: string
  net_buy: number
  seat_type: 'INSTITUTION' | 'HOT_MONEY'
  continuous_days: number
}
```

---

### 8.5 模块三：操作原则与交易纪律（AI 总结）

#### 8.5.1 设计定位

这是 **AI Agent 的“风险控制人格”**。

- 明确给出：
  - 今日是否适合操作
  - 重点观察方向
  - 明确禁止行为（如冰点期追高）

#### 8.5.2 数据结构

```ts
interface TradingPrinciple {
  date: string
  market_emotion: 'ICE' | 'NEUTRAL' | 'HOT'
  allow_trade: boolean
  focus_themes: string[]
  risk_warning: string
}
```

---

### 8.6 与 AI Agent 后端的协同逻辑

每日复盘数据来源并非人工输入，而是：

1. AI 自动汇总当日事件流
2. 聚合题材 → 生成题材事件链
3. 结合涨幅、连板、龙虎榜生成情绪判断
4. 输出结构化 DailyReview

```ts
DailyReview = {
  date,
  theme_reviews[],
  dragon_tiger_list[],
  trading_principle
}
```

---

### 8.7 实施路径建议

**Phase 1（V1）**
- 人工触发生成每日复盘
- 结构化展示（不追求自动评分）

**Phase 2（V2）**
- 自动生成
- 题材阶段识别
- 与次日策略联动

---

## 九、总结

每日复盘模块的引入，意味着你的系统从：

> **“AI 帮你看盘” → “AI 帮你形成交易体系”**

这是一个质变，而不是功能叠加。


该前端系统的本质是：

> **把 AI 对市场的理解，转译成交易者可以“看得懂、跟得上、用得快”的工作台。**

只要这一点成立，产品就具备长期价值。

# 六、每日复盘页（Daily Review）页面 PRD 与组件树设计（V1 核心）

## 6.1 页面定位（Why）
每日复盘页是 **AI 投资助理的“记忆中枢”与“认知闭环节点”**，用于沉淀当日市场的结构性信息，为：
- 次日盘前决策（Morning Brief）
- 题材生命周期判断
- 龙头股持续性评估
- 交易原则自我校正
提供长期可回溯的数据基础。

该页面不追求“信息全”，而追求 **认知准、逻辑闭环、可复用**。

---

## 6.2 页面信息架构（What）

整体采用 **纵向时间流 + 模块化卡片结构**，从“市场整体 → 题材 → 个股 → 原则”逐层收敛。

### 页面结构分区
1. 顶部：复盘日期 & 市场概览（Summary Bar）
2. 模块一：当日核心题材复盘（Theme Review）【核心】
3. 模块二：资金与龙虎榜验证（Capital & LHB）
4. 模块三：交易原则与纪律（Trading Principles）

---

## 6.3 模块一：核心题材复盘（Theme Review Module）

### 6.3.1 模块目标
- 回答三个关键问题：
  1. 今天市场**真正认可**的题材是谁？
  2. 题材是启动、发酵、分歧还是衰退？
  3. 是否具备跨日持续性？

### 6.3.2 展示形式
- ThemeReviewCard（纵向列表，可折叠）

每个题材卡片包含：
- 题材名称 + 阶段标签（启动 / 主升 / 分歧 / 衰退）
- 当日关键事件摘要（AI 提炼）
- 市场情绪判断（强 / 中 / 弱）
- 资金验证结论（认可 / 分歧 / 证伪）
- 关联龙头股入口

---

## 6.4 模块二：资金与龙虎榜验证（Capital Validation Module）

### 6.4.1 模块目标
用于对 **AI 逻辑判断进行资金层面的硬验证**，避免“只讲故事”。

### 6.4.2 展示内容
- 龙虎榜摘要列表（按题材聚合）
- 关键游资 / 机构行为标注
- 资金态度结论（支持 / 中性 / 否定）

该模块结果将反向影响：
- 题材置信度
- 次日关注级别

---

## 6.5 模块三：交易原则与纪律（Trading Principle Module）

### 6.5.1 模块定位（非常重要）
这是 **AI Agent 的“风险控制人格”**，用于约束系统输出的激进程度。

### 6.5.2 内容结构
- 当日市场特征总结（如：情绪高位 / 缩量轮动）
- 明确可执行原则（如：不追高、不做弱转强）
- 禁止行为清单（AI 自动生成 + 人工可修订）

## 6. 每日复盘 → 次日盘前必读 自动生成工作流设计

### 6.1 设计目标
将“人工每日复盘”转化为系统级输入信号，自动生成 **次日盘前必读**，实现从主观判断到客观执行的闭环，而非简单文本拼接。

核心目标：
- 让盘前必读“有因有据”，每一条建议都可追溯到前一日复盘
- 降低盘前信息噪音，只输出经过复盘验证的高置信度内容
- 形成可自我修正的交易认知循环

---

### 6.2 核心工作流（逻辑分层）

#### Step 1：复盘数据入库（人主导）
来源：`daily_review`
关键字段：
- 核心题材判断（theme_judgement）
- 当日市场情绪定性（market_emotion）
- 龙头持续性观点（leader_continuity_view）
- 操作反思与纪律（trade_reflection）

此阶段不做 AI 干预，保证“人类第一性判断”。

---

#### Step 2：AI 复盘理解与结构化（AI 主导）
模块：`review_interpreter`

AI 任务：
- 抽取可执行结论（Execution Signals）
- 将主观语言映射为结构化字段
- 标记不确定性与冲突观点

输出示例：
- 可跟踪题材列表
- 风险提示题材列表
- 需验证的关键假设

---

#### Step 3：与题材 / 龙头引擎交叉验证（系统自动）

对接模块：
- `theme_daily_state`
- `leader_score_daily`

校验逻辑：
- 复盘主观判断 vs 客观数据
- 若一致 → 提升置信度
- 若背离 → 标记为“需重点观察”而非直接否定

---

#### Step 4：盘前必读内容生成（AI + 规则混合）
模块：`morning_brief_generator`

生成原则：
- 不追新：优先延续昨日复盘中的高置信度题材
- 不泛化：所有观点必须能反查来源
- 有排序：按“确定性 > 风险收益比 > 可操作性”排序

内容结构：
1. 市场情绪基调（继承复盘）
2. 今日重点题材（含复盘溯源）
3. 核心观察标的（非推荐，明确观察逻辑）
4. 明确风险与否定条件

---

#### Step 5：执行反馈预埋（为下一次复盘服务）

系统在生成盘前必读时，自动生成：
- 今日验证指标
- 关键失效条件

这些字段将自动出现在 **下一次每日复盘表单中**，形成真正闭环。

---

### 6.3 工作流逻辑图（文本示意）

```
人工复盘输入
      ↓
AI 复盘理解
      ↓
题材 / 龙头交叉验证
      ↓
盘前必读生成
      ↓
盘中观察 & 执行
      ↓
验证结果回流
      ↓
下一次复盘
```

---

### 6.4 设计优势总结

- 不是“写给自己看的复盘”，而是“写给系统用的判断”
- 盘前必读不再依赖当日情绪，而是延续认知主线
- 每一次复盘都在训练系统，也在校准交易者本身

### 9.10 `/intel` 三栏联动规则（固定语义）

- 右栏刷新主题级验证

2. 中栏点击事件：
- 更新 `activeIntelItemId`
- 若事件含 `stockId`，同步更新 `selectedStock`

- 更新 `selectedStock`

- 左栏主题保持不变

4. 日期切换：
- 更新 `recapDate`
- 三栏同时刷新
- SSE切为该日期回放/静态模式
