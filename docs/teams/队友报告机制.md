# 队友报告机制

## 概述

本文档定义了所有开发团队成员的报告机制和沟通规范，确保架构监督团队能够及时了解项目进展、处理关键决策和协调跨模块工作。

## 报告规则

### 1. 任务进度报告规则

#### 报告时机
- **每完成一个任务步骤**: 必须立即发送进度报告
- **遇到阻塞问题**: 阻塞超过2小时必须报告
- **里程碑达成**: 重要里程碑完成时即时报告
- **每日工作结束**: 发送当日工作汇总

#### 报告内容格式
```
【进度报告】模块名称/任务ID
报告时间: YYYY-MM-DD HH:MM
报告人: 姓名/角色

📊 当前状态:
- 任务步骤: [步骤名称]
- 完成情况: [已完成/进行中/阻塞]
- 进度百分比: XX%

✅ 已完成工作:
1. [具体完成内容1]
2. [具体完成内容2]

🔧 正在进行:
- [当前正在处理的内容]

🚧 遇到的问题:
- [问题描述，如有]
- [已尝试的解决方案]

📋 下一步计划:
1. [下一步工作1]
2. [下一步工作2]

⏰ 预计完成时间: [日期/时间]
```

#### 报告渠道
- **即时报告**: 使用SendMessageTool发送给架构师
- **正式记录**: 更新任务管理系统状态
- **团队同步**: 在团队频道中简要同步

### 2. 关键决策授权规则

#### 需要授权的决策类型
1. **技术方案决策**
   - 新技术栈引入或替换
   - 架构模式变更
   - 性能优化方案
   - 安全策略调整

2. **API设计决策**
   - 新增API接口设计
   - 现有API重大变更
   - API版本升级
   - 接口协议变更

3. **数据模型决策**
   - 数据库表结构变更
   - 数据迁移方案
   - 缓存策略调整
   - 数据一致性方案

4. **外部依赖决策**
   - 第三方服务集成
   - 开源库引入
   - 云服务使用
   - 外部API调用

#### 授权请求流程
```
1. 识别决策点
   ↓
2. 准备决策请求文档
   ↓
3. 提交权限请求
   ↓
4. 等待架构师评估
   ↓
5. 接收授权决策
   ↓
6. 记录决策到ADR
```

#### 决策请求文档模板
```
【决策授权请求】决策类型/模块名称
请求时间: YYYY-MM-DD HH:MM
请求人: 姓名/角色

🎯 决策概述:
- 决策标题: [简短描述]
- 决策类型: [技术方案/API设计/数据模型/外部依赖]
- 紧急程度: [高/中/低]

📝 决策背景:
- 问题描述: [需要解决的问题]
- 当前状况: [现状分析]
- 决策必要性: [为什么需要此决策]

💡 建议方案:
- 方案描述: [详细的技术方案]
- 技术细节: [实现方式、技术选型等]
- 预期效果: [期望达成的目标]

🔍 方案评估:
- 优点: [方案的优势]
- 缺点: [方案的不足]
- 风险: [可能的风险和应对措施]
- 影响范围: [影响的模块和功能]

🔄 备选方案:
- 方案B: [备选方案描述]
- 方案C: [其他考虑方案]

📊 决策建议:
- 推荐方案: [方案A/B/C]
- 推荐理由: [为什么推荐此方案]
- 实施计划: [如果通过，如何实施]

⏰ 决策时限: [期望的决策时间]
```

### 3. 每日工作汇总规则

#### 汇总时间
- **每日下班前30分钟**: 发送当日工作汇总
- **每周五下午**: 发送本周工作汇总
- **每月最后工作日**: 发送本月工作汇总

#### 汇总内容格式
```
【每日工作汇总】姓名/角色 - YYYY-MM-DD
发送时间: YYYY-MM-DD HH:MM

📈 今日完成:
1. [任务1] - [状态] - [完成度]
2. [任务2] - [状态] - [完成度]
3. [任务3] - [状态] - [完成度]

🎯 关键成果:
- [最重要的成果1]
- [最重要的成果2]

🚧 遇到的问题:
- [问题1] - [状态] - [负责人]
- [问题2] - [状态] - [负责人]

🤝 协作事项:
- [需要协作的事项1]
- [需要协作的事项2]

📋 明日计划:
1. [计划任务1] - [优先级]
2. [计划任务2] - [优先级]
3. [计划任务3] - [优先级]

💡 改进建议:
- [对流程/工具的改进建议]
- [对团队协作的建议]

📊 工作量统计:
- 有效工作时间: X小时
- 会议时间: Y小时
- 阻塞时间: Z小时
```

#### 汇总发送方式
- **邮箱系统**: 发送到架构监督团队邮箱
- **抄送**: 抄送直接上级和项目负责人
- **归档**: 自动归档到工作记录系统

## 工具配置

### SendMessageTool配置
```yaml
# SendMessageTool配置文件
messaging:
  # 接收者配置
  recipients:
    - name: "首席架构师"
      channel: "architecture-supervision"
      priority: "high"
    
    - name: "模块架构师"
      channel: "module-architecture"
      priority: "medium"
  
  # 消息模板
  templates:
    progress_report: "【进度报告】{module}/{task_id}"
    decision_request: "【决策授权请求】{decision_type}/{module}"
    daily_summary: "【每日工作汇总】{name}/{role} - {date}"
  
  # 发送规则
  rules:
    - type: "progress"
      trigger: "task_step_complete"
      required: true
      timeout: "5min"
    
    - type: "decision"
      trigger: "key_decision_point"
      required: true
      timeout: "15min"
    
    - type: "blocking"
      trigger: "blocked_over_2h"
      required: true
      timeout: "immediate"
```

### 权限同步系统配置
```yaml
# 权限同步系统配置
permission_system:
  # 决策类型映射
  decision_types:
    technical_solution: 
      approvers: ["首席架构师", "相关模块架构师"]
      sla: "4小时"
    
    api_design:
      approvers: ["首席架构师", "后端架构师"]
      sla: "8小时"
    
    data_model:
      approvers: ["首席架构师", "数据架构师"]
      sla: "8小时"
    
    external_dependency:
      approvers: ["首席架构师", "基础设施架构师"]
      sla: "24小时"
  
  # 审批流程
  approval_flow:
    - step: "提交请求"
      action: "developer_submit"
    
    - step: "架构师评估"
      action: "architect_review"
      timeout: "根据SLA"
    
    - step: "决策反馈"
      action: "decision_notification"
    
    - step: "记录决策"
      action: "adr_recording"
  
  # 通知规则
  notifications:
    - event: "request_submitted"
      channels: ["email", "slack"]
    
    - event: "decision_made"
      channels: ["email", "slack", "sendmessage"]
    
    - event: "sla_violation"
      channels: ["email", "slack", "sms"]
```

## 执行监督

### 报告合规检查
1. **自动检查规则**
   - 任务步骤完成是否及时报告
   - 关键决策是否经过授权
   - 每日汇总是否按时发送
   - 报告格式是否符合规范

2. **合规指标**
   - 报告及时率 ≥95%
   - 决策授权率 100%
   - 报告完整率 ≥90%
   - 格式规范率 ≥95%

3. **违规处理**
   - 首次违规: 提醒和指导
   - 重复违规: 记录和警告
   - 严重违规: 通报和整改

### 质量评估
1. **报告质量评估**
   - 内容完整性
   - 问题描述清晰度
   - 解决方案可行性
   - 建议价值度

2. **决策质量评估**
   - 决策依据充分性
   - 方案评估全面性
   - 风险识别准确性
   - 实施计划可行性
