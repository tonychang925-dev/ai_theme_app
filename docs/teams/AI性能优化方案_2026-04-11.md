## 二、优化方案

### 2.1 批量处理优化

#### 2.1.1 批量API调用
```python
class BatchDeepSeekParser:
    """批量DeepSeek API解析器"""
    
    async def parse_news_batch(self, news_items: List[Dict]) -> List[Dict]:
        """批量解析新闻"""
        # 合并多个新闻到一个API调用
        combined_prompt = self.build_batch_prompt(news_items)
        batch_result = await self.parse_content_batch(combined_prompt)
        return self.split_batch_results(batch_result, news_items)
```

#### 2.1.2 批量大小策略
- **小批量**：2-5条（低延迟，适合实时处理）
- **中批量**：5-10条（平衡延迟和吞吐量）
- **大批量**：10-20条（高吞吐量，适合离线处理）

### 2.2 缓存优化

#### 2.2.1 结果缓存
```python
class CachedEventExtractor:
    """带缓存的AI事件提取器"""
    
    def __init__(self, redis_client):
        self.redis_client = redis_client
        self.cache_ttl = 3600  # 1小时缓存
    
    async def extract_event_with_cache(self, news_data: Dict) -> Dict:
        """带缓存的AI事件提取"""
        cache_key = self._generate_cache_key(news_data)
        
        # 检查缓存
        cached_result = await self.redis_client.get(cache_key)
        if cached_result:
            return json.loads(cached_result)
        
        # 调用AI分析
        result = await self.extract_event(news_data)
        
        # 缓存结果
        if result and result.get("status") == "success":
            await self.redis_client.setex(
                cache_key, 
                self.cache_ttl,
                json.dumps(result)
            )
        
        return result
```

#### 2.2.2 缓存策略
- **相似新闻去重**：基于标题和内容哈希
- **热点新闻缓存**：高频访问的新闻延长缓存时间
- **缓存预热**：预加载热门新闻的分析结果

### 2.3 异步并发优化

#### 2.3.1 并发处理池
```python
class ConcurrentProcessor:
    """并发处理器"""
    
    def __init__(self, max_concurrent=10):
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.task_queue = asyncio.Queue()
    
    async def process_concurrently(self, items: List[Dict]) -> List[Dict]:
        """并发处理多个项目"""
        tasks = []
        for item in items:
            task = asyncio.create_task(
                self._process_with_semaphore(item)
            )
            tasks.append(task)
        
        results = await asyncio.gather(*tasks, return_exceptions=True)
        return self._filter_results(results)
```

#### 2.3.2 动态并发控制
- **基于负载调整**：根据pending消息数量动态调整并发数
- **错误率控制**：错误率升高时降低并发数
- **资源监控**：监控CPU/内存使用率

### 2.4 模型优化

#### 2.4.1 Prompt优化
- **精简Prompt**：减少不必要的上下文
- **结构化输出**：使用JSON Schema约束输出格式
- **上下文压缩**：压缩新闻内容，保留关键信息

#### 2.4.2 模型选择
- **小模型**：DeepSeek-Coder-V2-Lite（更快响应）
- **量化模型**：INT4量化（减少内存和计算）
- **本地部署**：考虑本地部署小模型

## 四、预期效果

### 4.1 性能目标
- **短期目标**：吞吐量提升5-10倍（0.09 → 0.5-1.0项/秒）
- **中期目标**：吞吐量提升20-30倍（0.09 → 2.0-3.0项/秒）
- **长期目标**：完全消除pending消息积压

### 4.2 资源需求
- **Redis内存**：增加缓存需要额外内存
- **API调用成本**：批量处理可能增加token使用量
- **计算资源**：并发处理需要更多CPU资源

### 4.3 风险控制
- **API限流**：DeepSeek API有调用频率限制
- **缓存一致性**：确保缓存结果及时更新
- **错误传播**：批量处理失败影响多条消息
