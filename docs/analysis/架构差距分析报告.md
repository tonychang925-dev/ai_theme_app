## 附录 B：JYHF 原始数据中 Leader/龙头标注来源调查

### 混合来源结构

| 来源 | 提供内容 | 强度 | 数据流路径 |
|------|---------|------|-----------|
| JYHF `*_stocks.jsonl`（文件行序） | 原始 `is_leader` bool（仅首只股票） | 弱 | `import_jyhf_stock_daily_incremental.py:197` → `subject_stock_daily_snapshot` |
| JYHF `children/*.jsonl`（子树层级） | 显式 `lead_stock_id` / `lead_stock_name` | **强** | `load_subject_children_staging.py` → `subject_children_staging` → `subject_stock_map` (`top=TRUE`) |
| `LeaderCandidateService`（规则打分） | `role_label` = 龙头/龙二/卡位/补涨/强趋势/套利/淘汰 | 程序衍生 | `build_theme_leader_candidate.py` + `leader_candidate_service.py` → `theme_leader_candidate` |
| LLM 裁决管线 | `leader_stock_id` + 确认依据 | 程序衍生（AI） | `build_theme_leader_llm_judgement.py` → `call_theme_leader_llm.py` → `apply_theme_leader_llm_response.py` |
| `LeaderboardProjector`（新链） | `role_name = "leader"`（按 `mainline_strength_score` 排序第一名） | 程序衍生 | `daily_snapshot_projector.py:135-168` → `ThemeStockLeaderboard` 冻结对象 |

### 关键结论

1. **JYHF 原始 JSONL 不含"龙头"中文标签**——`role_label` 的中文值（龙头/龙二/等）全部由 `LeaderCandidateService.assign_role_label()` 在程序运行时生成
2. **JYHF 提供两个弱/强原始信号**：文件行序 `is_leader`（弱）和子树 `lead_stock_id`（强）。`lead_stock_id` 是 JYHF 显式标注的题材龙头，是可信度最高的原始信号
3. **新链（SPS）的 leader 标注更简单**：`LeaderboardProjector` 仅按 `mainline_strength_score` 排序取第一名，不使用 LLM 或多因子规则
4. **盘后报告"强势股分层"混合使用旧链数据**：`LLM裁决角色` 和 `回退规则角色` 字段表明，旧链优先使用 LLM 裁决，LLM 未覆盖时回退到规则候选

### 影响建议

- **迁移时需评估新旧链 leader 一致性**：SPS 的 `LeaderboardProjector` 与旧链 `LeaderCandidateService` 的排名逻辑不同，可能导致同一题材的龙头标注不一致
- **如需保留 LLM 裁决能力**：应在 SPS 的 `LeaderboardProjector` 中增加 LLM 裁决回退机制，或单独构建 LLM 裁决服务
- **JYHF 原始 `lead_stock_id` 可作为黄金标注源**：可在 SPS 中增加从 `subject_stock_map` 读取 JYHF `lead_stock_id` 的逻辑，作为 leader 标注的权威基准
